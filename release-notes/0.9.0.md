# Release notes for pkpdsim 0.9.0

pkpdsim 0.9.0 adds the command `pkpd_release`, which makes the complete release of the repository of a model (e.g. `hctz-model`) from its model package, the same way for every model.

## New features

### The release of a model repository
`pkpd_release PACKAGE --version X.Y.Z [--repo PATH] [--no-publish] [--pkpdsim-path PATH] [--workers N]` (package `pkpdsim.release`, see the docs page "Release of a model repository"):

- **Export** of the files git tracks in the model folder into `src/<package as folders>/` of the release repository, without the excluded paths (by default `TODO.md`, `literature/` and `thesis/`).
- **Project files** from templates of pkpdsim: `pyproject.toml` (the dependencies of the source, constrained to the versions of its `uv.lock`), `Dockerfile`, the CI and docs workflows, `zensical.toml`, `.zenodo.json`, `.gitignore`, `.python-version`.
- **Build** in the environment of the release repository: the models and the COMBINE archive, the simulations and, for a model with adopted fits, the simulations with the confidence interval and the reports of the adopted fits (`run_report <package> --adopted`), copied to `fit/<fit id>`.
- **Release notes** generated from the changes since the previous release: the core libraries (pkpdsim, sbmlsim, sbmlutils), the changed dependencies, the data, the models, the experiments and the fits.
- **Docs**: a Zensical site (home, running, models, simulations, fit, release notes) with the links to the simulation and fit reports, and a short README.
- **Manifest and prune**: `release.json` records the version, the commit of the monorepo, the versions of the core libraries and a hash of every generated file; every file which the release does not generate is removed. A build reviewed with `--no-publish` is published without a rebuild.
- **Publishing**: the Docker image is built (for `linux/amd64`) before anything is published, then the commit, the tag, GitHub Pages, the push, the push of the image (`:<version>` and `:latest`) and the GitHub release with the archive. Every step is skipped when it is done, so a failed or interrupted release is finished by running the same command again; a failed or interrupted build records the files it changed, so a file added by hand is still refused.

### The release metadata of a model
`PKPDModel.release` takes the release metadata of a model, a `ReleaseSettings` with its `Author`s (`pkpdsim.release.settings`): the title, the GitHub repository, the concept DOI, the authors, the keywords, the Docker image, the funding, the description, the excluded paths and the year of the first release. A model without it cannot be released.

### The record of an adopted fit
`pkpdsim.reports.adopted_record(model, fit_id)` returns the record of an adopted fit and checks that its subset has a fit definition and that the record has its `parameters.json`; `adopted_reports` uses it.

## Fixes
- `fit_subset` refuses a fit id with a path separator or `..`, so that the id is safe as the name of a directory.

## Dependencies
- `jinja2` renders the templates of a release repository as well (it was already a dependency).
- `pyyaml` in the `dev` extra, for the tests of the workflows of a release repository.
