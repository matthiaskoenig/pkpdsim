# Release notes for pkpdsim 0.25.0

Every command says what it is doing: `--progress` renders the progress of the runs of a command, which sbmlsim 0.23.0 reports for the experiments of a simulation, the points of a scan, the runs of a fit with the points of their jacobians, the scans of an identifiability and the figures of a report.

## Features

- **The option `--progress` says how the progress of the runs of a command is shown** ([#190](https://github.com/matthiaskoenig/pkpdsim/pull/190)). `--progress MODE` anywhere after the model package chooses the rendering, `auto` (the default), `bar`, `log` or `none`, and is taken out of the arguments before the parser of the command sees it, as `--profile` is. It sets `SBMLSIM_PROGRESS`, so every run of the command and every process it starts reads it, i.e. `run_simulation`, `run_fit`, `run_report`, `run_identifiability` and `run_credibility`. The events of the progress are written into the `progress.jsonl` of a run whatever is chosen. The names of the renderings are given in the command module and not imported from `sbmlsim.progress`, so a command still runs on an sbmlsim without the module, where the option has no effect.

## Dependencies

- `sbmlsim>=0.23.0`, which carries `sbmlsim.progress`, the progress of the long runs, and writes the uniform of the bounds for a parameter whose standard error covers them, so a model with a rank deficient Fisher information can be built.
