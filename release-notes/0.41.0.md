# Release notes for pkpdsim 0.41.0

pkpdsim moves onto sbmlsim 0.42, whose figures are drawn by the renderer of sbmlsim-core: every figure of a model run is fast, interactive in the reports and drawn without matplotlib. matplotlib and seaborn are no longer dependencies of pkpdsim, and the zonation figures are ported from matplotlib to the chart builder `sbmlsim.plot.chart`, which changes their API.

## The renderer

The floors are `sbmlsim>=0.42.1` and `sbmlsim-core>=0.29.0`. Every figure of a model run is drawn by the renderer of sbmlsim-core: it is fast, interactive in the reports (a legend entry toggles its group, a click selects a curve) and imports no matplotlib. sbmlsim 0.42.1 takes every colour name of matplotlib, such as `tab:grey`.

matplotlib and seaborn are no longer dependencies of pkpdsim. A model package which draws its own figures in `figures_mpl()` must declare matplotlib itself. sbmlsim warns once per experiment class which does and recommends the chart builder.

The figure formats are `svg` and `png`, plus a `json` spec written beside each image whatever the formats. `html` is gone, the reports are interactive with the renderer instead. `savefig_dpi` applies to PNG only.

## Zonation figures

Every figure function of `pkpdsim.zonation.figures` returns a `sbmlsim.plot.Chart`, which is saved with `chart.save(path)` and no longer with `savefig`, and has a `title` where it had a `suptitle`.

API changes:

- `draw_lobule(ax, ..., mappable=)` is `draw_lobule(plot, ..., scale=ColorScale)`.
- `colorbar(figure, mappable, ax, **kw)` is `colorbar(plot, scale, label)`.
- `fill_band` takes a `ChartPlot`, and `data_axes` returns plots.
- New: `lobule_axes(aspect, *, label, labels)`, `panel_aspects`, `ColorScale` and `space_time(log=)`.
- Removed: `COLORBAR`, `NO_LEGEND`, `HEATMAP_HEIGHT` and `OUTFLOW_HEIGHT`.

Behaviour changes:

- A single frame has one legend per row.
- `space_time` refuses fewer than two time points, non-finite times and unsorted times.
- `draw_lobule(labels=True)` raises a `ValueError` when its axes leave no room for the names, instead of clipping `PT` without a word.

A model which composes a grid of lobules of its own makes the plots with the axes of `lobule_axes`, builds its chart once, measures the layout with `panel_aspects` and builds it again with the measured aspects:

```python
def lobules(aspects):
    chart = Chart(460.0, 230.0, columns=2)
    plots = []
    for column in (0, 1):
        x, y = lobule_axes(aspects.get(f"p{column}"), labels=True)
        plots.append(chart.plot(0, column, x=x, y=y, legend=False))
    draw_lobule(plots[0], values, scale=scale, anatomy=True, labels=True)
    draw_lobule(plots[1], values, scale=scale, anatomy=True)
    return chart


figure = lobules(panel_aspects(lobules({})))
```

The full example, with the colour bar and the missing zones, is in `docs/zonation.md`.

## Known limitations of the renderer

The renderer lacks three things, tracked in matthiaskoenig/sbmlsim-core#107:

- There is no hidden axis line, so the lobule panels show an L of axis lines.
- There are no error-bar caps.
- There is no equal aspect, which is why `lobule_axes` and `panel_aspects` exist: they make the hexagon regular by the limits of its axes.

## Dependencies

- `sbmlsim>=0.42.1`.
- `sbmlsim-core>=0.29.0`, a direct dependency now, since the browser example scripts and the zonation figures import it.
- `matplotlib` and `seaborn` are removed from the runtime dependencies.
