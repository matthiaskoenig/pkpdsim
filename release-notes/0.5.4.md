# Release notes for pkpdsim 0.5.4

pkpdsim 0.5.4 draws the figures of the sensitivity runner without pyplot. Nothing else changes; the saved figures are byte for byte the same.

## Development

- The tox environments (`py3.13`, `py3.14`, `ty`) are created from `uv.lock` (`runner = uv-venv-lock-runner` of `tox-uv`, which the `dev` extra now contains, with the extra `dev`) instead of from the newest releases of PyPI; the package is still built as a wheel and installed. Why: the `ty` environment took ty 0.0.87, which refused code that the locked ty 0.0.86 accepts, so a check differed from the one of the lock.

## Fixes

- The box, violin and points figures of the `SamplingAnalysis` (`sampling_N<n>_sensitivity_samples.png`, `..._outputs.png`) are drawn on `matplotlib.figure.Figure` (`Figure()` and `fig.subplots`) instead of `plt.subplots`, and the `plt.close` calls (they freed pyplot figures) and the import of `matplotlib.pyplot` are removed from `pkpdsim.sensitivity`. Why: a pyplot figure belongs to the interactive backend. With TkAgg and a display next to a pool of processes, its Tk objects are collected by the garbage collector in a thread other than the main one, and the process aborts (`RuntimeError: main thread is not in main loop`, `Tcl_AsyncDelete: async handler deleted by the wrong thread`, exit 132); the midazolam sensitivity run of pkdb_models hit it ([sbmlsim#317](https://github.com/matthiaskoenig/sbmlsim/issues/317)). The tests have a `no_pyplot` fixture (`pyplot.figure` raises) for the figures of every analysis, and one that no module of pkpdsim imports pyplot. The `plt.close("all")` after each heatmap and index figure freed figures of sbmlsim, which draws them on `Figure` since 0.9.3 (the `sbmlsim.sensitivity.plots` docstring), so nothing needs it.
