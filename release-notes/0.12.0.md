# Release notes for pkpdsim 0.12.0

pkpdsim 0.12.0 reads the studies of format 2 of pkdb_data, keeps the scans of the steps of the integrator small in memory, and makes the release repositories of the models support python 3.14 and 3.15 and refuse files which GitHub rejects. The simulations and the fits are unchanged.

## Dependencies

- pkpdsim depends on `pkdb>=0.12.17`, the library of PK-DB, which reads and validates a study of format 2 as `pkdb check` does ([#81](https://github.com/matthiaskoenig/pkpdsim/pull/81)).

## Changes

- **The studies of format 2 of pkdb_data** ([#81](https://github.com/matthiaskoenig/pkpdsim/pull/81)).
  - **Before.** `collect_tsv_files` refused a study of format 2 (#74), so the data of the models could not be synchronized with pkdb_data, which is curated in format 2 throughout.
  - **Now.** A study of format 2 is read with `pkdb.prepare` (with the `vocabulary.lock.json` of the checkout) and written as the hidden tables of format 1, which the experiments read unchanged:
    - one table per source with the reported outputs and timecourses; an output gets the label of its measurement, substance, tissue, interventions and subject, and the missing sd, se and cv are calculated as PK-DB does;
    - the scatters of a source as the table `<source>Scatter`, a point with its values in `x` and `y`;
    - `TabGroups`, `TabIndividuals` and `TabInterventions`, a repeated dose with its interval and number of doses.
  - **Unchanged.** A study of format 1 is copied as before; another format is an error before anything is written. `database_differences` compares the studies with a PK-DB server by the digest of their sources.
- **A ragged scan is on the time points of a figure** ([#85](https://github.com/matthiaskoenig/pkpdsim/pull/85)).
  - **Before.** `state_after_changes` interpolated every simulation of a result onto the union of the time points of all its simulations. For a scan of the steps of the integrator that union grows with the square of the number of simulations: a scan of chlorzoxazone over 100 draws of the fitted parameters took more than 40 GB.
  - **Now.** A ragged result of several simulations is interpolated onto the time points of a figure (`plot_times`: a few hundred, dense where the simulations stepped densely, with the times of the changes), as `point_band` does for the draws. One simulation keeps its own time points, a result on a grid is unchanged, and a result whose union has fewer time points than a figure keeps them all.
  - **Analyses.** An analysis which reads values of a result (the NCA, a value at a time) should read the result of the task itself, the steps of the integrator, not the result on the grid of a figure.
- **The release repository supports the Python versions of the monorepo** ([#83](https://github.com/matthiaskoenig/pkpdsim/pull/83)).
  - The Python versions are those of the classifiers of the monorepo (`Programming Language :: Python :: X.Y`), e.g. 3.14 and 3.15: the `pyproject.toml` of the release names them, the job `simulate` of its CI runs on every one and the Python badge of the README and the docs names them.
  - The Docker image, `.python-version` and the docs workflow keep the Python of the monorepo.
- **A release refuses a file which GitHub rejects** ([#84](https://github.com/matthiaskoenig/pkpdsim/pull/84)).
  - **Before.** A file above 100 MB was committed and tagged and failed at the push (HTTP 500): the release of captopril-model committed 174 netCDF results of up to 5.5 GB of a model with `save_results`.
  - **Now.** The stage *Prune and manifest* refuses such a file before the commit, the tag and the Docker image, and names the files with their size.
