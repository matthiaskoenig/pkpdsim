# Release notes for pkpdsim 0.3.1

Support of the rollout of the model object to the models of pkdb_models (matthiaskoenig/pkdb_models#95).

## New features

- `pkpdsim-verify settings` writes what a run of the experiments of a model hands to sbmlsim as json: the arguments of `SimulatorSerial`, of `ExperimentRunner` (without the simulator) and of the run (without the output path), bound to their signatures, the attributes of `Figure`, the matplotlib `rc` settings a run changes, and the counts of calls. It works with or without a model object and exits with 2 for an incomplete run. Why: the settings of every model are compared mechanically between a checkout before and after the switch to the model object
- `pkpdsim-verify dump --rtol model` (and `--atol model`) take the tolerance of the model object, any other value which is not a number exits with 2. Why: a model keeps its tolerances in one place, the comparison uses them on both sides

## Changes

- `run_<model>` of a model without experiments (`experiments=None`): `--action factory` creates its models, `--action all` runs only the factory, `simulate` and `list_experiments` are a usage error with a message. Why: models like limax have a factory but no experiments and get a console script
- `fit_<model>` states in its description and in the help of `--identifiability` what the default of the model is. Why: the default differs between models
- `testing.check_model` checks the name against the package, that `model_path`, the factory directory and `archive_path` lie below the path of the model, and that the data paths exist. Why: a model folder must be exportable into a repository of its own
