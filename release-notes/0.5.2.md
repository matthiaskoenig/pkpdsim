# Release notes for pkpdsim 0.5.2

pkpdsim 0.5.2 adds the runner of the sensitivity analyses of a script to `pkpdsim.sensitivity` and makes the names of the units of the data of an experiment public. It changes no behavior of a model of pkdb_models: the hctz script on the runner writes the same tables and figures as its own copy of the runner, byte for byte.

## Features

- `pkpdsim.sensitivity.SensitivityRunner` runs the sensitivity analyses of the script of a model: a script gives its model object, a function which gives its parameters, its outputs (`SensitivityOutput`, the id of the tables and figures and the id of the observable), its observables and its analyses by name (`LocalAnalysis`, `SamplingAnalysis`, `FastAnalysis`, `SobolAnalysis`, each with its groups, `SensitivityGroup`, and its `delta` or number of samples), and runs them with `SENSITIVITY.main()` from its command line or with `run(names, path=..., simulator=...)`. A run writes the table of the parameters into `results/sensitivity` of the model and the tables and figures of an analysis into `<analysis>/<group>`, with the simulator of the model and `n_workers=None`; an analysis varies the `free_parameters` of its groups, `PKPDSIM_SENSITIVITY_N` replaces its number of samples. A runner whose outputs, groups, sizes or default analyses do not fit together is a `ValueError` when it is created. Why: the port of the models onto sbmlsim 0.9 copied the same runner (about 180 lines) into the script of every model, hctz, apixaban, rivaroxaban and losartan so far and twelve by the end, where a change of a table or a figure would have to be made in every copy. The run of hctz with the sizes of a smoke run (`local` complete, `sampling` and `sobol` with 16 samples, `fast` with 65) gives the 92 files of its copy, byte for byte.
- `PKPDSimulationExperiment.data_unit_names()` gives the names of the units of `data_units` (read-only, defining the units on its first call), for a table which a model reads itself, e.g. the data of the figure of a scan: `rename_units(df, self.data_unit_names())`. It replaces the private `_data_unit_names()`. Why: the scan of the parameters of apixaban called the private method.
