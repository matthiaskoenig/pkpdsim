# Release notes for pkpdsim 0.38.0

The libraries of the day: `sbmlsim>=0.40.0`. One evaluation of the objective of a fit now uses the CPUs of the machine instead of the thread of its caller, which is the part of a model analysis that was leaving cores idle, and four smaller changes of sbmlsim reach a model package without moving a number. Nothing of pkpdsim's own code changed since 0.37.0, and no fitted, simulated or generated number of a model moves.

## Dependencies

- **`sbmlsim>=0.40.0`**, on the same floor of the engine, `sbmlsim-core>=0.25.0`.

### One evaluation of a fit uses the whole machine (sbmlsim 0.40.0)

An evaluation of the objective is one simulation per group of fit mappings and the groups do not depend on each other, but only a batch of parameter vectors - the points of a jacobian, the members of a population - was handed to the engine as a batch. A single evaluation ran its groups one call at a time on the thread of its caller, however many CPUs the machine had.

The parts of a model analysis which spend their time in single evaluations are the ones this reaches: a point of a profile likelihood, the polishing step of a differential evolution, the evaluation of a report. On the HCTZ PK problem of pkdb_models, 49 groups and 160 mappings over 20 CPUs, ten evaluations of `residuals` at the model values go from 102.4 ms to 62.9 ms each, with cpu/wall from 1.00 to 3.03. A worker of a pool keeps its one thread, since the processes of the pool already use the CPUs of the machine, so a fit whose repeats run in parallel is unchanged.

The residuals of a batched evaluation are the serial ones bitwise. No number of a model moves and no analysis gives another answer; what changes is how long it takes.

### A change which sets a concentration by a formula (sbmlsim 0.40.0)

`sbmlsim.simulator.formula.linear_form` decides whether the value of a change is a linear form the engine evaluates from its own state or a number folded at the point the request was built. It parsed the formula with the parser of PEtab math without escaping the two selections of roadrunner that parser cannot read, the bracketed concentration `[S]` and the dotted observable `pk.cmax`, so such a formula raised and every caller folded it - and because a request writes its formulas as forms all or nothing per plan, one such formula folded every formula of its plan.

**No model package of pkdb_models is affected**: a check across all 47 packages found no change whose value is a formula reading a bracketed concentration. Every `Change` value is a quantity or a python expression evaluated before the plan, and the bracketed target of simvastatin's `modeltest_liver` is a target, not a form. A model which does write such a formula gets a form which follows the search where it got a frozen number, which is what a form is for.

### A stored parameter set says which of its values were applied (sbmlsim 0.40.0)

A value a problem neither fits nor uses in a noise model changes no simulation: the model keeps its own. `ParameterSet.unapplied` is the mark of those values, and it reaches the `parameters.json` of a fit report, the record of an adopted fit and the `credibility.json` of an assessment, so a reader of that evidence can tell a number which was simulated from one which was only carried. A set whose every value took effect carries no mark and writes no key, so such a file of a model package is the file of pkpdsim 0.37.0 byte for byte, and an older file reads back with an empty mark.

### The places of a plan (sbmlsim 0.40.0)

Whether a fit of a model runs in the engine or in python is decided by walking the places of a plan which carry a value, and that walk was written twice in two functions which had to agree and which nothing compared. They read one enumeration now, so a place a later change adds reaches both and gets the conservative answer, a gap, until it is given a rule. A plan which carries a pre-initialization for the steady state after the end of a simulation is refused rather than silently dropped by every engine, which is what used to happen.

## The browser exports

The four committed browser exports of the documentation are written again with `scripts/cardiovascular_examples.py` and `scripts/lobes_examples.py`, because they record the version of sbmlsim they were produced with.

A leaf by leaf comparison of the four datasets against the committed ones shows **exactly one differing value per file, `sbmlsim_version`**. Every precomputed course is identical to the last bit, and the compiled model descriptions and the vendored runtime of the engine are untouched, the core release not having moved.

## Unchanged

- `sbmlsim-core>=0.25.0`, `sbmlutils>=0.17.3`, `pymetadata>=0.9.0`, `pkpdutils>=1.7.1` and `libroadrunner>=2.12.0.dev714` are unchanged, each is still the release pkpdsim was tested against.
