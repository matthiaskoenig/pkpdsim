# Release notes for pkpdsim 0.5.0

pkpdsim 0.5.0 runs on sbmlsim 0.9 and lifts the cap of 0.4.1. It requires sbmlsim 0.9.3 (the run order of the per-state tolerances, events with units, data units with a factor).

## Features

- `SimulatorSettings.n_workers` and the option `--workers` of `run_<model>` (a number, `auto` or `model`); an extra action gets the settings of the simulator of the run as `options.simulator`. Why: sbmlsim 0.9 runs the points of a scan in a pool of processes. The default is serial (`1`), because a pool needs the guard `if __name__ == "__main__":` in the script, multiplies the memory of a run and changes nothing in the results; `None` leaves the choice to sbmlsim.
- `pkpdsim.experiment.to_sid` and the method `to_sid` of `PKPDSimulationExperiment`. Why: sbmlsim 0.9 requires the keys of an experiment (datasets, simulations, tasks, figures, fit mappings) to be SIds, and the models built them from labels with spaces, dots and dashes. The function maps a text character by character (a decimal point between two digits is `p`, every other character outside `[A-Za-z0-9_]` is `_`), so a part of a key gives the same part of the SId. The method raises a `ValueError` naming both texts when two texts of an experiment give one SId, which would silently replace an entry of a dict. sbmlsim checks the validity of a whole key (not empty, not starting with a digit) when the experiment initializes.
- `PKPDSimulationExperiment.data_units`, `pkpdsim.experiment.define_unit` and `rename_units`. Why: the data of a study use units which sbmlsim does not define, e.g. an international unit, which is specific to a substance. The experiment defines them under a name of the model and the substance (`IU_ramipril_renin`) before the data are read, and the loaders rename them in the unit columns (the unit alone or after a metric prefix, so `µIU/ml` is renamed and `IU_per_ml` stays). sbmlsim's unit registry exists once per process and ignores a redefinition, so `define_unit` raises a `ValueError` for a name which is defined with another value instead of silently giving a second model the first one, and for an expression which pint cannot evaluate. `initialize` defines the units, so a refused definition fails the initialization of its experiment, which the run reports with its other failures, and does not stop the run.
- `pkpdsim.scan` (`single_dimension`, `point_timecourse`). Why: sbmlsim 0.9 returns a scan with the layout `(*dims, time)` and the states before and after a change at the time of the change; the pharmacokinetic parameters and figures of the scans of the models read one point as sbmlsim 0.8 gave it (the state after the change only), so their numbers stay the same.
- `pkpdsim.sensitivity` (`parameters_from_sbml`, `set_bounds`, `set_relative_bounds`, `parameters_to_df`, `write_parameters`, `distributions`, `sample_size`). Why: sbmlsim 0.9 dropped the table of the parameters of a sensitivity analysis, which the sensitivity scripts of the models write next to their results; it is the table of sbmlsim 0.8 (the same values, columns and LaTeX), and the distributions are the input of the global designs of sbmlsim 0.9. `PKPDSIM_SENSITIVITY_N` replaces the sample size for a quick run of the scripts. `jinja2` is a direct dependency for the LaTeX table.
- `pkpdsim-verify compare` compares a dump of sbmlsim 0.8 with one of sbmlsim 0.9: the time dimension first and the other dimensions by name, the rows of a repeated time matched from the last one (the state after a change, which is all sbmlsim 0.8 had), the count of the states before a change per experiment, a row at a time which only the old dump has always a difference and one which only the new dump has a difference which the results pattern `experiment/task/time` names. A figure of sbmlsim 0.8 is compared with the one of sbmlsim 0.9 in the form of sbmlsim 0.9: the settings it set as attributes with the settings of its experiment and its own, its size with the size it is rendered with (a dump stores both, `__resolved__`), and the fields which only sbmlsim 0.9 has (`sel`, `over`, `_bands`) are listed instead of compared. The renames file has the new parts `ids` (old id to new id), `sids` (every id becomes its SId), `figure_fields` (fields of a figure which `compare` cannot map, left out at the level of the figure) and `expected` (patterns of the differences which are expected, `experiment/task/variable`, `experiment/mapping` and so on; a bracket is literal). `png --sids` pairs an old figure with the new figure of the SId of its name. A dump records the versions of sbmlsim and pkpdsim. Why: a port to sbmlsim 0.9 changes the layout of the results and the ids of the experiments, and the verification of a model must say exactly what changes instead of passing with a weaker comparison or failing on every array.
- `pkpdsim.run.create_simulator(settings)`, the sbmlsim `Simulator` of `SimulatorSettings`, and `simulator=` of `PKPDModel.run_experiments` and `run_simulation_experiments`, other settings of the simulator for one run. Why: a script or an extra action with a runner of its own (the CYP2C9 analyses of glimepiride) simulates with the tolerances and the processes of the model, and a run can take another number of processes without a second model object.
- `load_dataframe(na_values=...)` takes the strings of missing values by column as well, e.g. `{"time": ["NR"]}`. Why: sbmlsim 0.9 refuses a text in a numeric column, and a study which writes `NR` for a time which is not reported needs it as missing in that column only, not in a column where `NR` is a value (a label).
- `default_fit_settings` passes `data_at_change=DataAtChangeType.BEFORE` to sbmlsim. Why: a data point at the time of a change after the start is compared with the state before the change, sbmlsim 0.9's default, written out so that a change of the default of sbmlsim does not change the fits of the models.

## Breaking changes

- pkpdsim requires `sbmlsim>=0.9.3,<0.10` (the cap `<0.9` of 0.4.1 is gone). Why: the port to sbmlsim 0.9, which renamed the simulator, the result and the figure settings. Migration: the models move to the API of sbmlsim 0.9.
- `pkpdsim.model.FigureSettings` derives from `sbmlsim.plot.FigureSettings`; its fields have the defaults of sbmlsim instead of `None`, the fields of sbmlsim can be given by position and `formats` and `savefig_dpi` only by keyword. `FigureSettings.applied()` and `FIGURE_ATTRIBUTES` are gone, and so is `pkpdsim.testing.restored_figure_settings`. Why: sbmlsim 0.9 takes the figure settings as an argument of the run instead of the class attributes of `Figure`, so nothing is applied to the process and there is nothing to restore. Migration: remove the calls; the settings of an experiment and of a figure override those of the model.
- `pkpdsim.model` imports `sbmlsim.plot` at runtime (the import takes about 0.7 s instead of about 0.014 s, measured with sbmlsim 0.9.3 on one machine; the number goes with sbmlsim). Why: `FigureSettings` derives from sbmlsim's class; `import pkpdsim` stays light.
- `run_<model>`, `PKPDModel.run_experiments` and `pkpdsim.testing` raise for failures: a run with a failed experiment or figure writes its report and its figures and then raises `sbmlsim.experiment.ExperimentRunError`, `run_<model>` runs its remaining actions, prints every failure and exits with 1, and `initialize_experiments`, `run_all_experiments` (also one at a time) raise one `AssertionError` which names every failure. Why: sbmlsim 0.9 logs a failed experiment and goes on, so a run with a broken experiment passed.
- `pkpdsim.fit.observable_id` is the `Data.index` of the observable of the mapping, and `observable_filter` selects by it. Why: sbmlsim 0.9 identifies the data of a mapping by `Data.index`, which is what a fit selects by.
- The settings json of `pkpdsim-verify settings` has `run.figure_settings` instead of `figure`, and `Simulator` instead of `SimulatorSerial`. Why: the figure settings are an argument of the run, and the class attributes of `Figure` are gone.
- `CheckSettings` refuses an empty `one_at_a_time` (a `ValueError`). Why: an empty reason hides why the experiments cannot run together.
- `pkpdsim-verify compare` is stricter: a row at a time which only one dump has is a difference (0.4.1 compared the common times only and passed), and the new part `expected` of the renames, which names an expected difference such as a new output time (`experiment/task/time`), fails for a pattern which matches no difference. Why: a time which one dump lacks is a changed simulation, which the comparison passed silently, and a renames file must say exactly what changes. Migration: a comparison which passed with 0.4.1 can fail with 0.5.0; a new output grid of a task is named with `expected`, an old time without a new one always counts.
- `pkpdsim-verify dump` without `--atol` simulates with the absolute tolerance of sbmlsim 0.9 (`AbsoluteTolerance()`, per kind of state) instead of the `1e-10` of sbmlsim 0.8's `SimulatorSerial`. Why: the dump takes the default of the simulator of sbmlsim. Migration: a dump of 0.4.1 and one of 0.5.0 without `--atol` differ by construction; pass the same `--atol` to both, `--atol model` for the tolerance of the model.
- `PKPDSimulationExperiment.tasks()` builds the tasks from the simulations which `initialize` created instead of calling `simulations()` again, so `tasks()` of an experiment which was not initialized is empty. Why: the simulations were created twice, and a model whose `simulations()` is costly (a scan with a design) paid it twice. Migration: call `tasks()` after `initialize` (the runner does); an override of `tasks()` which calls `simulations()` itself keeps working.

## Fixes

- `pkpdsim-verify dump` records an experiment which cannot be initialized as an error and exits with 1; sbmlsim 0.9 logged it and the dump said `ok`.
- `pkpdsim-verify compare --renames`: the `strings` rename was applied to the names of the parts of the dump too (`mappings` became `mbppings`), so any rename of a text which occurs in them broke the comparison; it renames the content of the parts only, and a rename which gives two keys one key is an error. `apply_renames` returns a new dump instead of changing the loaded one.
- `PKPDSimulationExperiment` creates the simulations once (`tasks` used a second call of `simulations()`), the loaders take `study is None` for the experiment's own study, `check_registry` computes the defined experiments once, and the `Q` imports are those of sbmlsim 0.9 (`from sbmlsim import Q`).
- `pkpdsim.verify.describe_mapping` no longer fails for a fit mapping without x values.
