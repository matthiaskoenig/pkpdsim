# Release notes for pkpdsim 0.4.0

## Features

- `pkpdsim.experiment.PKPDSimulationExperiment`, the base of the simulation experiments of a model. It is bound to the model object by the class attribute `pkpd_model`, has the conventions `selections`, `Mr`, `labels` and `units`, and provides `models`, `tasks`, `default_changes`, `data`, `load_dataframe`, `load_dataframes_by_substance` and `figures_by_sid`. Why: the `base_experiment.py` of the 45 models repeated the same code, which now lives once.
- `pkpdsim.impairment` (the presets of the renal function, the cirrhosis and the cardiac function with their colors) and `pkpdsim.pk` (`PK_LABELS`, `PK_UNITS`), the defaults of the base. Why: the models defined the same classes, factors and labels again and again; a model chooses a preset or adds a class to it.
- `pkpdsim.metadata`: the shared closed vocabularies `Tissue`, `Route`, `Dosing`, `Fasting`, `ApplicationForm`, `DataType` and `PKPDData` as `StrEnum`s, and `PKPDMappingMetaData`, the metadata of a fit mapping which a model extends with its own fields (`to_dict` shows the member names). Why: the studies of all models are described with the same words, which the filters of the fits rely on.
- `pkpdsim.fit.metadata_filter`, `observable_filter` and `select_mappings`. Why: the filters of the `mapping_collections.py` of the models are the same lambdas on the metadata; they are built once, check their fields when the module is imported (a misspelled field is an error, not an empty selection), have a readable `repr`, and `select_mappings` takes the paths from the model object.
- `pkpdsim.model.CheckSettings` and `PKPDModel.checks`: the not registered experiments, the modules which do not import and why the experiments run one at a time, each with its reason; an exception which no longer applies fails the tests. Why: the exceptions were parameters of the test functions in every model; as part of the model object they are one place and cannot go stale.
- `pkpdsim-verify compare --renames FILE` applies the expected renames of a migration (metadata fields, members and added fields, texts) to the old dump before the comparison. Why: moving the models to the shared metadata renames fields and members, which showed every mapping as changed and hid the real differences.
- The user guide page "Experiments and their metadata" describes all of the above.

## Breaking changes

- `pkpdsim.testing` reads the exceptions from `model.checks`; the parameters for exceptions of its functions are removed. Why: one source for the exceptions instead of a parameter per call. Migration: move them to `checks=CheckSettings(...)` of the model object.
- `pkpdsim-verify` describes only packages with a model object; a package without `MODEL` exits with code 2. Why: all models have one, and the commands work with it instead of guessing the layout of a package.
