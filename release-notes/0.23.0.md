# Release notes for pkpdsim 0.23.0

The build of a machine perfusion model takes an extension of a package, so a mechanism which the library does not have is written where its elements belong: the cells of the mechanism into the cell model of the zones, its constants into the liver and the rest into the composed model. The reperfusion injury of the machine perfusion model of pkdb_models is the first extension; it could not be built on 0.22, which made the cells of a zone a submodel. pkpdsim 0.23.0 runs on sbmlsim 0.18, like 0.22, 0.21 and 0.20.

## Features

- **An extension of the build of a perfusion model** ([#181](https://github.com/matthiaskoenig/pkpdsim/pull/181)). `pkpdsim.perfusion.PerfusionExtension` is a mechanism a package adds to the model of its definition, which `build`, `compose`, `zone_cell_model` and `create_archive` take: `cell` extends the cell model of the zones once, `shared` names the elements of the cell model which the liver holds once, `expose` the states of the cells which the liver reads or a figure draws, and `composed` extends the composed model after the build has placed the circuit, the zones and the observers. The engine exposes the species and the reactions of the extension per zone under the ids of the perfusion, as it does those of the library (`hmgb1_z1_cell`, `HMGB1R_z1`), a shared constant is one element of the flat model instead of one per zone, so a fit has one value of it, and an exposed state is `<id>_<zone>`, which the observers of the liver can name (`bs_z1`); without it a state of the cells stays `M<kk>__<id>`, which exists in no model until the flattening. A shared id which the composed model does not hold is refused by `compose` with the ids named, instead of failing in the comp package of the written model. The docs page `perfusion.md` has the section, `tests/perfusion/test_builder.py` the four tests.

## Differences users see

- A build without an extension writes the model of 0.22, line by line: the stored references of the perfusion tests are unchanged.
- The constants which the liver shares are now those which the cell model still holds after an extension ran, instead of the full list of the cellular core, so an extension which replaces a law of the library removes the constants of that law from both models and the flat model holds them neither once nor per zone. Without an extension the list is the one of 0.22.
- The quantities the cells exchange are now those of the chain which the cell model has a port for, instead of a fixed list of the library, so a quantity of the perfusate which an extension exchanges is wired to the vascular space of its zone like the quantities of the library. For the cell model of the library the two lists are the same.

## Dependencies

- No changes; sbmlsim 0.18 (`>=0.18.0,<0.19`).
