# Release notes for pkpdsim 0.3.0

## New features

- `pkpdsim.model`: `PKPDModel` describes a model once, in the `__init__.py` of its package: its paths, its factory, the registry of its experiments and its fit definitions (references resolved on use), the settings of its simulator and figures, and the actions it adds to its commands (matthiaskoenig/pkdb_models#95)
- `pkpdsim.run`: the simulation experiments of a model run with its settings, the figure settings are restored after a run
- `pkpdsim.cli`: the commands `run_<model>`, `fit_<model>` (with the identifiability analysis of the fitted parameters), `report_<model>` and `identifiability_<model>`
- `pkpdsim.fit`: the fit settings the models share, the metadata check and the observable of a fit mapping
- `pkpdsim.testing`: the tests of a model as functions, `check_model` checks that a model object belongs to its package and that its references resolve
- `pkpdsim.verify`: the command `pkpdsim-verify`, the verification of a change of a model (from `scripts/verify_model.py` of pkdb_models), with the new subcommand `definitions`. `png` and `sbml` compare directories recursively by relative path and exit with 2 for a missing directory or without files, and `--root` is checked to be the place the model package was imported from. `dump --atol helpers` became `--atol model`: the tolerance of the model object, or of `helpers` of a package of the old conventions

## Changes

- `PKPDModel`, `FigureSettings`, `SimulatorSettings` and `ExtraAction` are keyword-only dataclasses; `data_paths`, `extra_actions` and the figure formats are stored as tuples (a list is accepted), and a bare string as formats is rejected
- `with_output_dir` puts the output directory of the model in front of the arguments, so an output directory in the arguments (also `--out`) wins
- A model with no fit definitions fails with a `ValueError` naming the model

## Dependencies

- `sbmlsim>=0.8.5`
- `numpy`, `matplotlib`, `pillow` and `python-libsbml` are declared, they are imported directly
