# Release notes for pkpdsim 0.2.0

The annotations of the compartments and the terms of use came unchanged from pkdb_models in 0.1.0 and carried its errors ([#4](https://github.com/matthiaskoenig/pkpdsim/issues/4)). This release corrects them.

**The SBML of a model built with pkpdsim changes**: the RDF annotations of its compartments and the license named in its notes. The simulations do not change, annotations and notes are metadata. A model picks up the corrections when it is created again with pkpdsim 0.2.0.

## Annotations

Every term of `pkpdsim.annotations.compartments` was resolved in the ontology it names (OLS4 for FMA, BTO, NCIT, UBERON, GO and OMIT, a terminology server for SNOMED CT) and its label compared with the compartment it annotates. The changes:

| compartment | before | after |
| ----------- | ------ | ----- |
| `colon` | `uberon/UBERON:000115`, an id with six digits which is no term | `uberon/UBERON:0001155` (colon) |
| `mu` (muscle) | `bto/BTO:0000511` (gastrointestinal tract, the term of `gi`) | `bto/BTO:0000887` (muscle) |
| `blood` | `fma/FMA:62970` (portion of plasma) | `fma/FMA:9670` (portion of blood) |
| `gu` (gut) | `fma/FMA:45615` (developmental gut, an embryonic organ part) next to `fma/FMA:7199` (intestine) | removed, `fma/FMA:7199` remains |
| `rv` (renal venous plasma) | `IS` renal vein (BTO, NCIT), i.e. the plasma annotated as the vein | `IS` plasma (`bto/BTO:0000131`, `ncit/C13356`) and `IS_PART_OF` renal vein (BTO, NCIT, FMA), like the hepatic vein `hv` |
| `parietal cell` | `http://snomed.info/id/57041003`, an url | `snomedct/57041003` (gastric parietal cell), written as `https://identifiers.org/snomedct:57041003` |
| `plasma membrane` | `GO:0005886`, without the collection ([pkdb_models#104](https://github.com/matthiaskoenig/pkdb_models/issues/104)) | `go/GO:0005886` (plasma membrane) |

The comments of `rv`, `kiv` and `fov` no longer call them hepatic vein, the comments of `ve` and `ar` name the venous and the arterial tree (`fma/FMA:50723`, `fma/FMA:50720`), and every resource carries the label of its term as a comment. All other terms were correct and are unchanged.

## Terms of use

`pkpdsim.templates.terms_of_use` names the Creative Commons Attribution-ShareAlike 4.0 International License ([CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)) with its link and badge instead of CC BY 4.0, so the notes of a model agree with the license text its COMBINE archive ships (`pkpdsim.licenses.License.CC_BY_SA_4_0`).

The terms of use are indented by four spaces, like the description of a model written as an indented triple quoted string. sbmlutils removes the indentation the lines of the notes have in common, so behind a description which is not indented the terms of use became a code block with their HTML escaped, which is what the example of the documentation showed. The example indents its description, and the documentation and the docstring of `pkpdsim.templates` explain why.

## Tests

- `tests/test_annotations.py`: every resource is written as `collection/term`, the collection is in the identifiers.org registry and the term matches the pattern of its collection (UBERON with seven digits, the registry accepts any number of digits); the check rejects the errors corrected here.
- The terms of use name the title and the link of the CC BY-SA 4.0 text which the models ship and are rendered as HTML in the notes of a model, and sbmlutils writes every annotation of a model as an identifiers.org url.
