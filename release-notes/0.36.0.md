# Release notes for pkpdsim 0.36.0

A refresh of the floors of the simulation stack, which was released as a whole today. Nothing of pkpdsim itself changed since 0.35.0, but two of the three floors carry real behaviour into a model package: sbmlsim 0.38.0 moves the objective of a parameter fit into the engine core, so a fit of a model of [pkdb_models](https://github.com/matthiaskoenig/pkdb_models) integrates its residuals with the CVODE of that engine and its fitted numbers can move in their last digits, and pymetadata 0.9.0 reads and writes the COMBINE archive of a model through a Rust extension, so pymetadata is no longer pure python and an install on a platform without a wheel of that extension needs a Rust toolchain. Both are worth reading before a model package is rebuilt or refitted against this release.

## Dependencies

- **`sbmlsim>=0.38.0`**, two minor releases up from the `>=0.36.0` of 0.34.0 and 0.35.0. 0.37.0 made the engine core (`Engine.CORE`, the Rust SBML engine of [sbmlsim-core](https://github.com/matthiaskoenig/sbmlsim-core) compiled to WebAssembly) the default engine of every `Simulator`, `SimulatorSettings`, `ExperimentRunner` and `OptimizationProblem` which names none, which is what pkpdsim 0.35.0 answered with the engine independent initial values of a substance. 0.38.0 moves the **objective of a parameter fit** into that engine: the residuals of a fit of a model package are built as one request of the contract `fit/1` and integrated by the engine instead of by roadrunner, and a fit whose mappings read several models, whose condition carries a value the engine evaluates from its own state rather than a number which goes stale as the optimizer moves, whose experiment defines a pointwise observable, whose data carries a measurement without information, or whose objective is a likelihood of any noise distribution of PEtab or a posterior with its priors, all run there as well.

- **A fitted number of a model package can move in its last digits.** This is the one consequence of the sbmlsim floor which reaches the numbers of a model. The engine core integrates with the tolerance vector of roadrunner but with a build of CVODE of its own, which chooses its own steps, so the residuals of a fit are not roadrunner's bitwise and the error of the engine is not bounded by roadrunner's: sbmlsim measures the error of the engine at 1.0003 of roadrunner's on the scan of three doses of its reference model and at 1.237 of it at the loose tolerances `rtol` 1e-8 / `atol` 1e-10, so the agreement of the two integrators is a matter of the tolerances a fit runs at and not a bitwise identity. A fit of a likelihood whose noise scale the fit estimates, of a Laplace noise, or of a posterior now runs its **optimizer** in the engine where it ran in scipy, so its optimum agrees with the one of scipy to the tolerances of the fit rather than bitwise, and the residuals of a correlated prior moved in their last bits with the whitening of `_Correlated`, which sbmlsim fixed into an explicit product so that python and the engine evaluate the same loop over the same numbers. A refit of a model package against this release therefore gives parameter values which agree with the adopted ones to the tolerances of the fit; a fitted value which moves materially is not this and is worth a look. The "Changed numbers" section of the release notes of sbmlsim 0.38.0 is the full account.

- **`pymetadata>=0.9.0`**, which makes pymetadata no longer pure python. `pymetadata.omex`, through which the COMBINE archive of a model is written (`pkpdsim.pbpk.archive` and `pkpdsim.perfusion.archive` reach it through `sbmlsim.release.archive.write_archive`), reads and writes an archive through [`pymetadata-core`](https://pypi.org/project/pymetadata-core/), a Rust extension, and there is no pure-python fallback; the public API of `Omex`, `Manifest` and `ManifestEntry` is unchanged, so the archive of a model is written through the same calls and carries the same entries, while the bytes of a member pymetadata writes anew are not the ones of 0.8.3. The core ships one abi3 wheel per platform which every CPython from 3.11 on installs, `manylinux2014_x86_64` and `manylinux2014_aarch64`, `macosx_10_12_x86_64`, `macosx_11_0_arm64` and `win_amd64`, so an install of pkpdsim on linux with glibc, macOS or 64 bit windows is a wheel install as it was. On every other platform, i.e. musl based linux (Alpine), linux on armv7, ppc64le or s390x, FreeBSD, 32 bit or ARM windows, or an implementation other than CPython such as PyPy, pip falls back to the source distribution of the core and compiles it, which needs a [Rust toolchain](https://rustup.rs), i.e. `cargo`; without one the install fails while `pymetadata-core` is built. Reading an archive is lazy now (`Omex.get_path` extracts a member when something asks for it) and a written archive is reproducible, identical content giving identical bytes, which is why the `manifest.xml` and the members written anew have other bytes than before: they carry the zip epoch as their modification time instead of the time of the write, and the deflate of the core is not the one of CPython's `zlib`. A member which is only copied keeps its bytes exactly.

- **`pkpdutils>=1.7.1`**, the floor of the non-compartmental analysis of the scans of a model (`pkpdsim.pk`). 1.7.0 still required `pkpdutils-core>=0.6.0,<0.7` of its Rust kernel, so an install of it could not resolve the kernel 0.7.0; nothing of pkpdutils itself changed with the fix and the numbers of an analysis are unchanged.

## The committed browser exports and two test windows

- **The browser exports of the documentation are written again** with `scripts/cardiovascular_examples.py` and `scripts/lobes_examples.py`, as every move of the engine core needs: the runtime of `docs/pbpk/examples/solver` (`engine.wasm`, `mathlib.wasm`, `sbmlsim-core.js`, and the new `compiler.wasm`, which `sbmlsim_core.runtime_wasm()` returns as a third module since the engine core 0.24.0) is the one of the installed release, and the `sbmlsim_version`, `sbmlsim_core_version` and `compiler` of the provenance of each export name it. The precomputed courses are **unchanged to the last bit**: `cardiovascular-data.json` and `lobes-data.json`, for both sexes, differ from the ones of 0.35.0 in those two recorded versions and in nothing else, so the engine core 0.24.0 reproduces the SUNDIALS IDA solutions of 0.14.0 exactly for the cardiovascular circuit and for the lobed livers of the three species.

- **Two windows of the tests were widened**, both of them the precision of an integration and neither a change of what is asserted. `tests/perfusion/test_experiment.py::test_the_value_at_the_time_of_a_change_is_the_value_before_it` compares the row before a medium change with the run which has no change: roadrunner gave the two the same steps and they agreed bitwise, while the engine core, which integrates the segments ending at the change with steps of its own, agrees to 4.1e-11 relative on `alt`, `ast` and `ldh`, whose concentrations are about 1e-6 and whose accuracy at the `absolute_tolerance=1e-14` of the run is about 3e-9 relative; `rel` went from 1e-12 to 1e-9, one decade looser than the `relative_tolerance=1e-10` the two runs are integrated at, and the structure of the output, two rows at the change with the state before it first, is asserted as before. `FIT_RTOL` of `tests/test_credibility_assessment.py`, the window within which the record of the toy of pkpdsim 0.19 is reproduced, went from 1e-6 to 1e-5: the objective of that fit runs in the engine now, which moved its `AFE` from 1.000848541045419 to 1.0008498702539537, 1.33e-6 relative, while every verdict, status, acceptance row, quantity, coverage and input of the record is unchanged.

## Unchanged

- `sbmlutils>=0.17.2` is unchanged, it is the latest release. `libroadrunner>=2.12.0.dev714` is unchanged as well: it is still the build sbmlsim compares the installed libroadrunner against at `import sbmlsim`, and the engine core, which simulates a model package by default, needs no roadrunner of its own.
