# Release notes for pkpdsim 0.9.1

pkpdsim 0.9.1 fixes and improves `pkpd_release`, found in the review of the dry run of the release of hctz-model 0.9.0 ([#52](https://github.com/matthiaskoenig/pkpdsim/pull/52)).

## Fixes

- The fit page of a release shows the table of every adopted fit as a table. The template ended the line of the report links with `{% endif %}`, whose newline `trim_blocks` removed, so the table followed the links without a blank line and rendered as a paragraph of pipes.
- The release notes compare only the values of parameters which have one: a parameter which an assignment rule or an initial assignment sets is no longer listed as a changed value (the cardiac output `QC` of hctz appeared as `6.4998e+06 → 6.4998`).
- The commands of a release (git, uv, docker, gh) do not inherit `VIRTUAL_ENV`. `uv run pkpd_release` sets it to the environment of the monorepo, and every uv call in the release repository warned that it does not match the project environment.
- The models page links the report of a model on SBML4humans by its current address, `https://sbml4humans.de/report?url=<url>` with the url quoted (template filter `query`); `/model_url?url=<url>` falls through to the home page of SBML4humans.

## Improvements

- The README and the documentation of a release start with the same badges: the DOI, the latest GitHub release, the documentation (the status of the docs workflow, linked to the site), CI, the Docker image (an image of Docker Hub only), the Python version and the licenses of the code (MIT) and of the models (CC BY-SA 4.0).
- The Docker image of a release installs with uv 0.13.1 instead of 0.11.16.
