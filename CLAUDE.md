# CLAUDE.md

This file provides guidance when working with code in this repository.

## Project

`pkpdsim` is a python package with the building blocks shared by physiologically based pharmacokinetic and pharmacodynamic (PBPK/PD) models in SBML, i.e., the models of [pkdb_models](https://github.com/matthiaskoenig/pkdb_models): what these models share moves here, so that the folder of a model imports nothing but itself and released packages ([pkdb_models#95](https://github.com/matthiaskoenig/pkdb_models/issues/95)). A library with the console scripts `pkpdsim-verify`, `pkpd_release` and the five commands of the models, `run_simulation`, `run_fit`, `run_report`, `run_identifiability` and `run_credibility`, which take the dotted name of a model package first. Requires python >= 3.14 (tested on 3.14 and 3.15), packaged with hatchling (version is read from `src/pkpdsim/__init__.py`).

## Commands

```bash
# environment (uv based)
uv sync --extra dev
uv run pre-commit install
uv lock                                  # after every change of a dependency in pyproject.toml

# tests
pytest                                   # all tests, in parallel with pytest-xdist
pytest -n 0                              # in one process, e.g. for --pdb
pytest tests/test_package.py             # single file
pytest tests/test_package.py::test_version  # single test
tox r -e py3.14                          # single tox env (py3.14, py3.15 available)
tox run-parallel                         # full matrix + ty, from uv.lock (runner uv-venv-lock-runner of tox-uv, extra dev), run before opening a pull request

# lint / format / types
ruff check
ruff format
tox -e ty                       # ty type check (config in [tool.ty] in pyproject.toml)
uv run ty check                 # same check, straight from the working tree

# docs
uv run zensical build --clean --strict
uv run python scripts/llms_txt.py
uv run zensical serve
```

`develop` is the default branch and takes every change through a pull request; direct pushes are rejected by the rulesets in `.github/rulesets/` (applied with `.github/rulesets/apply.sh`), which require the `tests`, `ruff`, `ty` and `docs` checks. Continuous integration is kept minimal: `tests` runs only `py3.14`, on linux, macos and windows, every workflow cancels a superseded run (`cancel-in-progress: true`), uv caches packages and interpreters, dependabot runs monthly. Python 3.15 runs only locally. `main` only tracks the latest release and is fast-forwarded by the `sync-main` job of the release workflow, never by hand.

Release steps are in `docs/development.md`: the release is prepared on a branch, `uvx bump-my-version bump [dev|major|minor|patch]` updates `src/pkpdsim/__init__.py`, `CITATION.cff` and `tests/test_package.py` and commits without tagging, and the tag (a plain version, `0.1.0`) is created on `develop` after the pull request was merged, which triggers the release job of `ci-cd.yml`: PyPI through the trusted publisher of the GitHub environment `pypi`, the GitHub release from `release-notes/<version>.md` (archived by Zenodo) and the fast-forward of `main`.

Documentation is [Zensical](https://zensical.org/): markdown sources in `docs/`, configured in `zensical.toml`, built into the gitignored `site/`. The API reference is rendered from the docstrings by mkdocstrings; a page in `docs/api/` is just `::: pkpdsim.<module>`. `scripts/llms_txt.py` runs after the build and writes `llms.txt`, `llms-full.txt` and the markdown of every page into `site/`. The pages of the PBPK library (`docs/pbpk/`) have generated tables (`scripts/pbpk_tables.py`), tested equations and inline SVG diagrams, see `pbpk/` below.

## Architecture

`src/pkpdsim/__init__.py` holds the version and nothing else, so `import pkpdsim` stays free of the heavy dependencies (`tests/test_package.py` checks it); every topic is a module of its own which a model imports directly. The content of the modules moved unchanged from the shared modules of pkdb_models (`pkdb_models/models/{templates,annotations,data,pkpd}.py` and the license files of the models) in 0.1.0, so that the SBML the models create stayed the same; 0.2.0 corrected the annotations and the license of the terms of use. A change of a text, a creator or an annotation changes the SBML of every model which uses it; the release notes name such a change.

**`templates.py`.** `creators` (a list of `sbmlutils.factory.Creator`, the model history of the SBML) and `terms_of_use` (markdown which the models append to their notes: the copyright of the year of the import, CC BY-SA 4.0, the license of the COMBINE archive, the disclaimer), filled from the private template `_TERMS_OF_USE` and the first creator.

**`annotations.py`.** `compartments`, the annotations of the recurring compartments keyed by their abbreviation in the models (`li`, `ki`, `gu`, `ve`, `ar`, `po`, `urine`, ...): lists of `(BQB qualifier, "collection/term")` pairs, which sbmlutils resolves via identifiers.org and writes as RDF. `tests/test_annotations.py` checks that every resource is written as `collection/term`, the collection is in the identifiers.org registry and the term matches its pattern (UBERON with seven digits, the registry accepts any number); whether a term means what its key says is checked against the ontology by hand, the comment behind a resource is its label.

**`data.py`.** `studies_dir()` returns the folder `studies` of a checkout of pkdb_data: the path of the environment variable `PKDB_DATA` (the constant `PKDB_DATA`; an empty value counts as unset), else `../pkdb_data` relative to the working directory; a folder which does not exist raises `FileNotFoundError` naming both, and a set variable which points nowhere is an error even when the default exists. `collect_tsv_files(source_dir, target_dir, filter_study=None, *, studies=(), keep_files=False)` writes the data of every study folder (and of the further folders `studies`, e.g. of another substance) into a folder of the same name in `target_dir` as the hidden tables of study format 1 which the experiments read (`.<study>_<source>.tsv`) and reports every file on the rich console of sbmlutils (it is a step of the `data/collect_data.py` script of a model): a study of format 2 is read with `pkdb.prepare` (`prepare_study`, the vocabulary of the checkout's `vocabulary.lock.json`, the reading and validation of `pkdb check`), its reported measurements become one table per source with `MEASUREMENT_COLUMNS` (individuals with their mean in `value`, a digitized error bar as the `sd`/`se`/`gsd` it names, the missing `sd`/`se`/`cv` calculated with `pkdb.domain.statistics.complete_statistics`, an output without a label labelled by `_label` from measurement, substance, tissue, interventions and subject, with the source appended when another source of the study has the label, a row with a `gmean` and no `mean` of the calculation `geometric mean` (`_calculation_type`; PK-DB defaults a group to `sample mean`), a row below the LOQ without a central value and with the calculation of its curve, the curator 0 of a curve of geometric means left out (`_series_calculations`), the interventions in the natural order of the format 2 cell, the records PK-DB normalizes or calculates left out) its scatters one table per source with `SCATTER_COLUMNS` (a point per row, the values in `x_value`/`y_value` and `x`/`y`, the time and interventions of each axis in `x_time`/`x_intervention`/..., the name of the scatter as `label`, count 1 for an individual or for points of a group with the same interventions and times, else the count of the group; `<source>Scatter` when the source also has measurements), plus `TabGroups`, `TabIndividuals` and `TabInterventions` (`study_tables`, `write_study_tables`, which replaces the earlier tables of the study unless `keep_files`); the counts are nullable integers (`INTEGER_COLUMNS`); a curated label which is no SId, the same output in two sources and the dropped curator 0 are a `CollectionWarning`; the hidden `.*.tsv` files of a study of format 1 are copied; another format is a `ValueError` before anything is written. Beside the tables of a study, `write_study_tables` (and `collect_tsv_files` for a copied study of format 1) writes the record `.<study>_study.json` (`StudyRecord`, `study_record_path`, `read_study_record`), the provenance of the data: `collected`, the day of the first collection (today for a new folder, kept from an earlier record, `None` for a folder with tables and no record, collected on an unknown day) with its `dating` (`collection`, or `git` with `dating_commit` from `scripts/backfill_study_records.py`, the one-off backfill of pkdb_models from its history: the earliest table commit or mention of the study in the python code of the model, moved back to the day of an adopted fit committed with the study present; `__post_init__` requires a dating exactly with a day, a record without `dating` reads as `collection`), `updated` (the latest collection), `released`/`pkdb_id` of the `release` of `study.json` (`None` unreleased), `source_digest` of PK-DB, `pkdb_data_commit`/`pkdb_data_dirty` of the checkout (`None` outside git), `tables` (sha256 by file, `table_digests`; `changed_tables(folder)` names the differences) and `versions`; read by the temporal validation of `credibility/temporal.py` and the study data of `credibility/studies.py`; tests of the script in `tests/test_backfill_study_records.py` on a git repository in `tmp_path`. `database_differences(study_folders, client=None)` compares the studies with a PK-DB server by the `source_digest` of their sources (`DatabaseDifference`; 404 is a difference, other client errors are raised). `mean_of_individuals` and `sampling_times` are helpers of the experiments on the tables. `pkdb` (python >= 3.14) is imported inside the functions, so `import pkpdsim.data` stays light; the tests read copies of `hydrochlorothiazide/Patel1984` and `Nilsen1989` (scatters) in `tests/data/pkdb_data`.

**`initial_values.py`.** `init_concentrations_changes(r, skey, value)` and `init_amounts_changes(r, skey, value)` return the changes (`{"[Cve_x]": value}` for concentrations, `{"Cve_x": value}` for amounts) which set a substance to the same value in every tissue of a roadrunner model, the urine excluded; `get_species_keys(skey, species_ids)` is the naming pattern `^[AC][a-z]+(_plasma)*_<skey>$` of the ids of the top model. sbmlsim takes the changes as `preinit_changes`.

**`timecourse.py`.** `SimPart(tend, changes, steps)` and `Simulation(sid, title, parts)` describe a simulation of a roadrunner model in parts, `run_simulation(r, sim)` resets the model (`resetAll`), runs the parts one after the other (the changes of a part set at its start with `setValue`, its timecourse `simulate(0, tend, steps)` from the state of the part before) and concatenates their timecourses into one `DataFrame` of the `timeCourseSelections`, the time continued over the parts (the index of each part starts at 0); it logs the integration time. The one runner of the tissue and perfusion models of pkdb_models (`tpm.spt`, `tpm.fat`, `misc.zonation`, `misc.pvl`, the zonation of gdeobdtpa), which had diverging copies with different default steps (pkdb_models#118): `steps` has no default. The script which runs a model loads it and sets its tolerances and selections. Not to be confused with the command `run_simulation` of a model package (`cli.py`, `run.py`), which runs the simulation experiments of sbmlsim.

**Licenses.** The texts of the licenses of a model are `sbmlsim.licenses` (`License`, `license_text`, `write_license`), which `pbpk.archive.create_archive` writes next to the models; the docs page `licenses.md` shows their use. The distrib formulas of the draws of a fitted parameter are `sbmlsim.distrib` (`parse`, `support`, `DistribFormula`), read by `uncertainty` and `pbpk.chemistry`; both are modules of sbmlsim without roadrunner, so `pkpdsim.pbpk` stays free of it.

**`model.py`.** `PKPDModel` is a `sbmlsim.project.Project` (a frozen pydantic model, `extra="forbid"`) and describes a model once, in the `__init__.py` of its package. The keywords of the model packages of pkdb_models are mapped onto the fields of the project by a before validator, only for keyword input (`PKPDModel(**data)` takes any keyword, so ty accepts the old keywords): `path` is `root` (the property `path`), `model_path` and `female_model_path` are the `variants` `male` and `female` (the values of `pkpdsim.sex.Sex`, the male build first; a variant which is no sex or a female first is a `ValueError`; the file of the male build as the female one is a `ValueError`), `data_paths` is `data_path` (the property `data_paths`, a tuple), `fit_definitions` is `fits` (the fit definitions of the project), `fits` as a sequence of fit ids is `adopted_ids` (the adopted fits; `adopted_fits()` maps them by subset, two fits of one subset raise), `fits_path` is `fits_dir`, `factory_path` is `factory_dir`, and a `FigureSettings` of pkpdsim as `figures` is split into `figure_settings` (`sbmlsim_settings()`) and `figures` (`outputs()`, a `FigureOutputs` of the formats and `savefig_dpi`), a plain sbmlsim `FigureSettings` goes to `figure_settings`; a keyword and its field together are a `ValueError`. `package`, `factory_dir` (the directory of the male build by default) and `fits_dir` (`factory_dir.parent / "fits"` by default) are narrowed to be always set, derived in the before validator from the raw values, relative ones relative to `root` as the fields resolve them; the factory directory lies inside the root (sbmlsim). `replace(**fields)` gives a changed copy by the names of the fields (`Project.replace`); with other `variants` or another `root` it derives the directories again when they are the derived ones and not given (as the dataclass did), a `FigureSettings` as `figures` replaces `figure_settings` too. `model_path` is the property of `Project` (the male build), `variant_path(variant)` any build. A model needs its build and its factory. `PKPDModel` keeps what is pkpdsim's: `title`, `archive_path`, `results_path` and the result directories as properties (`results_dir`, `simulation_dir`, `uncertainty_dir`, `fit_dir`, `report_dir`, `identifiability_dir`, `credibility_dir`, below the package, which phase 3 of the consolidation removes), `reduced_selections`, `save_results`, `fit_identifiability`, the `ExtraAction`s of `run_simulation` and `extra_arguments` (references checked when the model is created, an action which repeats an action of `RUN_ACTIONS` or another is a `ValueError`), `adopted_ids` and `fit_records()`, `model_paths` (`Sex` to build), `female_model_path`, `model_path_of(sex)` (a `ValueError` naming the model and `female_model_path` for a sex without build), `load_roadrunner(sex)` (a build at the level of the model, the loader of the tests of a model), `load_credibility()` (a `TypeError` for a reference which is no `pkpdsim.credibility.Credibility`) and the known failures of the battery checked against `BATTERY_CHECKS` of `credibility/verification.py`. The default simulator of a model is `DEFAULT_SIMULATOR`, `SimulatorSettings(absolute_tolerance=1e-10, relative_tolerance=1e-10)` of sbmlsim; the processes belong to the run, `RUN_WORKERS` (1, serial, so a script without the guard `if __name__ == "__main__":` runs) is the default of `run_experiments` and `run_simulation_experiments`, which keep their signatures of the model packages (`experiment_classes`, `output_dir` below `simulation_dir`, the result a `Path`; they override `Project.run_experiments`, `ty: ignore[invalid-method-override]`) and gain `n_workers`. The fit definitions of `load_fit_definitions()` carry the level of `SimulatorSettings.jit_optimization` (`FitDefinition.jit_optimization` of sbmlsim), so the problems of the fits, their reports, the identifiability analysis, `start_fits` and `pkpdsim-verify fits` load their models at it in every worker. `SimulatorSettings`, `CheckSettings`, `resolve`, `check_reference`, `normalize_formats` and the release settings (`sbmlsim.release.settings`) are sbmlsim's, `fit_subset` and `FIT_ID` are `sbmlsim.fit.result`'s and `adopted_record` is `Project.adopted_record`; pkpdsim re-exports none of them. `sex.py` holds the enum `Sex` alone, imported by the model object and by the library, which re-exports it, so that neither imports the other. `pkpdsim.model` imports `sbmlsim.plot` and `sbmlsim.project` at runtime, because `FigureSettings` derives from sbmlsim's. The model has no entry points of its own, the commands of `cli.py` resolve it by its package.

**`run.py`.** `run_experiments` and `run_simulation_experiments`: the run of experiment classes with the settings of the model (`create_simulator(settings, n_workers=RUN_WORKERS)` makes the sbmlsim `Simulator` of the `SimulatorSettings` of sbmlsim with the processes of the run, `simulator=` replaces the settings and `n_workers=` the processes for one run, serial by default, the `figure_settings` of the model go to sbmlsim's run and `figures.rc_params()` into a matplotlib `rc_context`); a relative output directory is below the simulation results of the model. A run which has a failed experiment or figure writes the report and collects the figures first and then raises `sbmlsim.experiment.ExperimentRunError`.

**`cli.py`.** The commands as functions of a `PKPDModel`: `run_command` (actions `factory`, `simulate`, `all`, `list_experiments` and the extra actions; `--experiments`, `--formats`, `--results-dir`, `--workers` (a number, `auto` or `model`, `parse_workers`; `model` is `RUN_WORKERS`, serial; an extra action gets the `SimulatorSettings` of the model as `options.simulator` and the processes as `options.n_workers`, an extra option of either name is a `ValueError`), `--open`; a failed run collects its failures, the remaining actions run and the command prints them and exits with 1), `fit_command` (the options of `sbmlsim.fit.cli.fit_cli` plus the identifiability options and `--start JSON_OR_FIT_ID`: least squares starts every run from the point, a json file of values by pid in the units of the fit parameters or the best parameters of an adopted or finished fit, on copies of the parameters with the sampling `START` of sbmlsim, so `--runs 1`; least squares otherwise samples its starts from the bounds and uses a start value only for an infinite bound; not with differential evolution; the provenance records `start`; `fit_command`, `report_command` and `identifiability_command` hand sbmlsim the definitions at the level of the model, `PKPDModel.load_fit_definitions`), `report_command`, `identifiability_command` and `credibility_command`. The console scripts (`run_simulation_main`, `run_fit_main`, `run_report_main`, `run_identifiability_main`, `run_credibility_main`, in `[project.scripts]`) all go through `main(name, argv)` and `COMMANDS`: the first argument is the dotted model package, `resolve_model` imports it and takes its `MODEL` (`ModelNotFoundError`, a usage error with exit 2, for a name which is no dotted package, a package or parent which is not found, no `MODEL`, a `MODEL` which is no `PKPDModel` or of another package; any other import error propagates with its traceback), a fit command needs fit definitions, the rest of the arguments goes to the command of the model, whose `prog` is `<command> <package>`; `--help` without a model prints the usage of the command (docs page `commands.md`).

**`fit.py`.** `start_point(model, definition, start, output_dir)` and `with_start(definition, point)` (the start of `run_fit --start`), `default_fit_settings` (`data_at_change` is sbmlsim's `DataAtChangeType.BEFORE`, the state before a change), `mapping_metadata` (the check of the metadata type, `PKPDMappingMetaData` by default, `TypeError`) and `observable_id` (the `Data.index` of the observable of the mapping); the filters `metadata_filter(metadata_type=PKPDMappingMetaData, /, *, excluded=None, **allowed)` (`MetadataFilter`, checked against the fields of the dataclass when it is built; the class is positional-only and passed only for a local extension; a single value, an empty set, an unknown field and an instance instead of the class are errors) and `observable_filter` (`ObservableFilter`); `select_mappings(model, experiment_classes, filters, outliers, validation)` selects with sbmlsim's `FitMappings` using the paths of the model object; `check_sampling_sites(fit_mappings, sites)` checks the resolved sampling site of every mapping against a table `{observable id: SamplingSite}` and returns one problem per mismatch or unknown observable (a model test asserts it is empty); `remainder_problems(sbml, parameters, fixed_values)` finds the remainders `1 - a - b` of the flat model (`REST` of `pkpdsim.pbpk`) whose fitted fractions can sum above 1 at their upper bounds (the values of the others from the fixed adopted fits or the model), `fit_command` refuses such a fit before it starts (the remainders of every build) (`parser.error`).

**`metadata.py`.** The one vocabulary of the fit mappings of all models, 13 `StrEnum`s: `Tissue`, `Route`, `Dosing`, `Fasting`, `ApplicationForm`, `DataType`, `PKPDData`, `Health`, `Coadministration`, `Genotype`, `Phenotype`, `AdministrationSite` and `SamplingSite` (the site of a blood sample, the observers of `pkpdsim.pbpk`), with the conventional members `HEALTHY`, `NONE` (nothing coadministered) and `NR` (not reported); a member has one name and one value in every model, a study which needs a new member adds it here, and a member whose meaning is not plain from its value is defined by a comment. The values are readable text (no `_`, a genotype starts with its gene) and API as much as the names: models look members up by value (`Genotype(f"CYP2C9 {genotype}")`, `Route(route)`). `PKPDMappingMetaData` is the keyword-only dataclass of `MappingMetaData` with 13 fields: `tissue`, `route`, `application_form` (default `NR`), `dosing`, `fasting` (`NR`), `health`, `coadministration` (`NONE`), `genotype`, `phenotype`, `administration_site`, `data`, `data_type` (all `NR`), `sampling_site` (`None` by default, what a study states; read the site with `resolved_sampling_site()`, never from the field: it follows the tissue without a statement by the table `_DEFAULT_SITES`, plasma, serum and blood `ARM_VEIN`, arterial blood and plasma `ARTERIAL`, saliva, urine, feces, feces and urine, bile and none `NOT_APPLICABLE`; `__post_init__` refuses a blood site on a tissue without a blood sample, `NOT_APPLICABLE` on a blood tissue and a site other than `ARTERIAL` on an arterial tissue, and `tests/test_metadata.py` classifies every member of `Tissue`, so a new member fails until it is in the table; `to_dict`, the filters and `check_sampling_sites` read the resolved site; appended last so the subclasses of the models stay valid); `to_dict` gives member names in the order of the fields. A model uses the class as it is and extends it only for a facet no other model has, with a subclass in its `fitting/mapping_collections.py` which adds fields and neither redefines a field nor repeats a vocabulary (e.g. a diplotype of the subjects).

**`experiment.py`.** `PKPDSimulationExperiment`, the base of the experiments of a model: bound to the model object by `pkpd_model` (a `TypeError` without), `selections`, `Mr`, `labels`, `units`, `sex` (the sex of the subjects, whose build the simulations run, `Sex.MALE` by default; a group whose majority is women runs the female build) and `simulation_sexes` (the key of a simulation to its sex where it differs from `sex`, declared and not computed, since the runner loads the models before `simulations()`); provides `models` (the build of `sex` as `model`, the build of another sex of `simulation_sexes` as `model_<sex>`, `model_id(sex)`, only the builds it simulates; a sex the model object has no build of is a `ValueError` naming the experiment), `tasks` (from the simulations `initialize` created, each on the build of `sex_of(key)`, a classmethod since the sexes are declared; a key of `simulation_sexes` which is no simulation is a `ValueError`), `default_changes` (none), `data`, `load_dataframe`, `load_dataframes_by_substance`, `figures_by_sid`, the method `to_sid` and the impairment and PK maps as class attributes. The method `to_sid` gives the SId of `sbmlsim.experiment.to_sid(text)` and raises a `ValueError` naming both texts when two texts of an experiment give one SId. `data_units` (class attribute, name in the data to the definition `<name> = <expression>`) defines the units of the data which sbmlsim lacks (an international unit) with `sbmlsim.units.define_unit(definition, ureg)` (raises a `ValueError` for a name which is defined with another value, since sbmlsim's registry is one per process and ignores a redefinition, so the name carries the model and the substance, `IU_ramipril_renin`, and for an expression pint cannot evaluate) in `initialize`, before the data are read, so a refused definition fails its experiment and not the run (sbmlsim's runner creates the experiments outside of its error handling; a loader called without `initialize` defines them on its first call), and the loaders rename them in the unit columns with `sbmlsim.data.rename_units` (the unit alone or after a metric prefix; `DataSet.from_df` of sbmlsim gives `gmean` the unit of its row and `gsd` `dimensionless`); `data_unit_names()` (public, read-only mapping, defines the units on its first call) gives the names for a table which a model reads itself (apixaban's scan of the parameters). `add_doses(times, doses, model="model")` returns the `Change` of repeated doses which add to their dose states (`"PODOSE_x + <dose in the unit of the state in the loaded model>"`), so the rest of earlier doses stays (pkdb_models#105); `ValueError` for a model which is not loaded. `across()` is the dimension of the draws of a run over them (`None` without) and `add_function(plot, task_id, y, label, color, linestyle="-")` a function of the results of a task as a curve of width 2.0 (`linestyle=None` gives the curve no line style) or, over the draws, the band of the run (the copies of inulin and gdeobdtpa and the `_across` of five scans).

**`pk.py`.** `PK_LABELS`, `PK_UNITS`, `nca_frame(result)` (a row per point: its position, every parameter with `<name>_unit`, `nca_flags`) and `scan_nca(res, key, *, dose, route, substance, lloq_fraction=None, options=None)`: the non-compartmental analysis of pkpdutils of a timecourse at every point of a scan as one batch (`ScanResult.to_timecourses`, `pkpdutils.nca`, the per-sample `lloq` relative to the maximum of every point), the parameters of `nca_single` per point to 1e-12, about 40 times faster for 200 points (pkdb_models replaces its per point loops of `nca_single`).

**`sensitivity.py`.** The helpers of the points of a scan (`single_dimension`, `scan_dimensions`, `point_timecourse`, `point_band`, `state_after_changes`, `start_values`, `end_values`) are `sbmlsim.result.scan`. `sensitivity` is the table of the parameters of a sensitivity analysis which sbmlsim 0.9 dropped (`parameters_from_sbml`, `set_bounds`, `set_relative_bounds`, `parameters_to_df`, `write_parameters` with `parameters.tsv` and `parameters.tex`, which needs jinja2) plus `distributions` (uniform in the bounds, the input of a global design), `free_parameters(parameters, simulations)` (the parameters which no simulation of the groups sets, in `preinit_changes` or a `Change`, logs the others; a global design must vary only these, sbmlsim 0.8.5 left the others out) and `sample_size` (the environment variable `PKPDSIM_SENSITIVITY_N` replaces the sample size for a smoke run), and the observables the models copied: `pk_observables(prefix, selection, outputs, *, dose, route, options, per_dose_mass, mr, pk_id)` (the `PK` analysis `pk_<prefix>` and a `Formula` `<prefix>_<key>` per output, an output of `per_dose_mass` divided by `at(<mr>, 0)`, which it requires) and `max_after_dose(time, values)` (the maximum of one selection from time 0 on). the doses before the initialization (`PODOSE_`/`IVDOSE_`/`SOLDOSE_`/`Ri_`, `DOSE_PREFIXES`) move to a change at the start; the sinks `Aurine_`/`Afeces_`, the intestine readouts which nothing drains (`Aabs_<s>` and `Aapp_<s>`, `GU__Aabs_<s>` and `GU__Aapp_<s>` with the readout `Fa_<s>` alone, since an endogenous substance which reaches the lumen at its baseline is absorbed again) and `resets` are set back at the start, a key of `resets` converted as the zeros (`[sid]` for a concentration species, the quantity of a PEtab condition); it refuses a dose before the initialization and at the start, a dimension over a dose the simulation does not give, a second presimulation, and a state which grows without an outflow and is not set back (`accumulating_states`/`growing_states`, checked once per model file); the `<id>_0` of a delta is set to its value after the equilibration; the species of the drugs are set to exactly 0 at the start, `drug_free_zeros(model_path, set_ids)`, since the residue of the presimulation (1.5e-29 mM in hctz) let pre-dose zero points into the fold metrics: the species of the substances without `baseline_<s>` (by `Mr_<s>`) which start at 0 and which no reaction feeds from a species with a start (a fed reactant, a fed product of a reversible reaction, a source which reads no dose id), minus what the condition, a dimension or a change at the start sets; the direction of a reaction for the zeros is its `reversible` flag, so a `CustomReaction` which can run backwards is written `A <-> B`; no steady state by `max_time` is sbmlsim's `SteadyStateError`; overloads for `Simulation`, `Scan` and the union, so a caller with both needs no `match`. The method calls `equilibrated_simulation(simulation, model_path, resets=, ...)` with the file of its loaded model (an error is noted with the experiment): the one equilibration, also outside an experiment, exported lazily from `pkpdsim.pbpk`; the names (`EQUILIBRATION_TOLERANCES`, `DOSE_PREFIXES`, `accumulating_states`, `growing_states`, `drug_free_zeros`, `equilibrated_simulation`, `Equilibration`) have the one import path `pkpdsim.pbpk.equilibration`. `Equilibration(resets=...)` is the function with which a sensitivity group equilibrates its scans (`SensitivityGroup(prepare=Equilibration(...))`), so the generic analyses import no module of the library. `flat_model.py` is the one reader of a built model for the equilibration and the kidney validity: `flat_model(path)` parses a flat file once per process (a `FlatModel` cached by path and modification time: species, parameters, accumulating states, the drug-free candidates and started species, concentrations, reactions, filtered substances, the flows of the kidney and their inputs), `loaded_model(path)` compiles it once at `O0` with the selections of both (`FlatModel.selections`), and `math_names` is the one walker of the names of a formula.

**Docs and diagrams.** The docs are tested: `tests/docs/test_pbpk_equations.py` builds toy definitions and finds every line of an ` ```equations ` fence of `docs/pbpk/*.md` (`<id> = <formula>`, `<id>: <reactants> -> <products> = <formula>`, `d(<id>)/dt = <formula>`, placeholders `<s>`, `<o>`) by id in the comp model with the same math (parsed, units of numbers dropped); `tests/docs/test_pbpk_ids.py` checks the id table of `docs/pbpk/index.md` against `pkpdsim.pbpk.ids`; the data tables of the pages (`docs/pbpk/*.md` and `docs/database.md`, the studies and the consensus of cirrhosis) are generated from the parameter database into the marked regions (`<!-- generated: <name> ... -->`) by `scripts/pbpk_tables.py` and `tests/docs/test_pbpk_tables.py` fails while a page is out of date (run `uv run python scripts/pbpk_tables.py` after a change of a table or a study). The diagrams are hand-written SVGs in `docs/pbpk/img/`, inlined into the page with `pymdownx.snippets` (`--8<-- "pbpk/img/<name>.svg"` in a `<div class="pbpk-figure" markdown="0">`, `docs/stylesheets/pbpk.css`), so `currentColor` and the CSS variables of the theme reach them; the classes and ids of a figure start with its own prefix (`pkc-` composition, `pkr-` circulation, `pko-` organ, `pkz-` zonated, `pkg-` intestine, `pki-` impairment), since the `<style>` of an inline SVG applies to the whole page.

The tests share the flat models of the session: `tests/conftest.py` patches `pkpdsim.pbpk.builder.flat_model` for the session (`flat_model_cache`) with a cache by the sha256 of the comp file without the dates of the model history, in a folder of the session which every worker of pytest-xdist shares (about a quarter of the builds of the suite repeat a comp model); a test which checks what the validation logs is marked `uncached_build`.

The tests of these modules run on the toy package `tests/pkpdsim_toy`; its SBML is created once per session by the controller (pytest-xdist), and a test writes only into `tmp_path`.

The PBPK tests compile their models at `O0` (`JIT_OPTIMIZATION` of `tests/pbpk/conftest.py`, the helpers `load`, `compiled`, `individual` and an autouse fixture which sets the default level of sbmlsim, not its environment variable, which a forkserver would keep); the compilation at `O2` was most of the time of the suite. Several individuals of one model come from `individuals(path)` (one loaded model, initialized for one individual after the other), not from a load per individual; `test_load_time` measures at `O2`, the snippets of the docs run at `O0`. The CI runs the tests of every platform in four jobs, `--shard I/4` (`tests/sharding.py`, by a hash of the test id).

## Conventions

- Type checking is done with [ty](https://docs.astral.sh/ty/). The optional extra `amici` (built from source, not in the dev environment) is an allowed unresolved import (`[tool.ty.analysis]`). `[tool.ty.terminal] error-on-warning = true` means warnings fail the check, so the tree must stay at zero diagnostics. Suppress a diagnostic with a rule-specific `# ty: ignore[rule-name]`, never a blanket `# type: ignore`. ty also runs as a pre-commit hook (`--extra dev`).
- Linting is ruff with the full rule set of the maintainer's packages including the annotations (`ANN`), see `.ruff.toml`; every module, class and function of the package carries full type annotations and a google style docstring (ruff `D`), `tests/` and `scripts/` are exempt from the docstring rules.
- Modules get their logger with `logging.getLogger(__name__)` and the package never configures logging; the console output of `collect_tsv_files` is the exception, it reports the copies of a script, and its findings for the curation are `CollectionWarning`s (`warnings.warn`).
- A dependency is only added for an import of the package; the floors in `pyproject.toml` are the releases the package was tested with. The exception is a floor of a security fix of a transitive dependency: `certifi>=2026.10.19` (GHSA-6q48-6c7w-9gw2, the CA bundle of requests, which sbmlutils and pymetadata use).
- `tests/conftest.py` loads the registry of identifiers.org, which sbmlutils resolves annotations with, into the cache of pymetadata once in the controller of the session; without it the parallel workers download it at the same time and the replace of the cache file fails on Windows (matthiaskoenig/pymetadata#102).
- `tests/docs/test_snippets.py` executes every ` ```python ` fence of every page of `docs/` in the order it appears, one namespace per page, in a subprocess with warnings as errors and a temporary working directory. A fence whose first line is `# not executed` is a fragment and is skipped. An output a page pastes has to come from a real run of that snippet.
- `uv.lock` is committed and pins the local development environment (`uv sync`, `uv run`, so also `uv run ty check`), the `documentation` workflow, which runs `uv sync --locked`, and the ruff version of the `ruff` workflow; the tox environments, i.e. the test matrix and the `ty` check of continuous integration, too (the runner `uv-venv-lock-runner` of tox-uv, `uv sync --locked` with the extra `dev`), so a source of `[tool.uv.sources]`, e.g. sbmlsim from git while the generic modules of pkpdsim move into it, holds everywhere. After changing a dependency in `pyproject.toml` run `uv lock`, otherwise the `documentation` workflow fails; `uv lock --upgrade` moves the lock to the newest releases. Dependabot bumps the lock monthly with `versioning-strategy: lockfile-only`, so the lower bounds in `pyproject.toml`, which users install against, are only changed by hand. The ruff and ty floors of the `dev` extra and the `rev` of their pre-commit hooks are the locked versions; update them together.
- libroadrunner links against `libpython`, which the interpreters of uv ship in their `lib` directory, outside the search path of the loader on Linux: export `LD_LIBRARY_PATH="$(uv run python -c 'import sys; print(sys.base_prefix)')/lib"` before running the tests (a system interpreter with its own `libpython` does not need it); the workflows do it in `.github/actions/setup`. tox takes the interpreters of uv only (`uv_python_preference = only-managed`; the libroadrunner 2.11.0 wheel for 3.15 needs `__jit_debug_register_code` of a `libpython` built with the experimental JIT, which deadsnakes lacks, sys-bio/roadrunner#1406) and its inline plugin `toxfile.py` puts the `lib` of the interpreter of each environment on `LD_LIBRARY_PATH`, so `tox` needs no export (without it roadrunner loaded the system's `libpython` of the same version, a second runtime in the process).
- Markdown carries no hard line wraps: a paragraph, a list item or a table row is a single line. Code fences, headings and the rows of badges keep their line structure.
- Release notes go in `release-notes/` as part of a release commit.
