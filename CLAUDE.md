# CLAUDE.md

This file provides guidance when working with code in this repository.

## Project

`pkpdsim` is a python package with the building blocks shared by physiologically based pharmacokinetic and pharmacodynamic (PBPK/PD) models in SBML, i.e., the models of [pkdb_models](https://github.com/matthiaskoenig/pkdb_models): what these models share moves here, so that the folder of a model imports nothing but itself and released packages ([pkdb_models#95](https://github.com/matthiaskoenig/pkdb_models/issues/95)). A library with the console scripts `pkpdsim-verify`, `pkpd_release` and the four commands of the models, `run_simulation`, `run_fit`, `run_report` and `run_identifiability`, which take the dotted name of a model package first. Requires python >= 3.14 (tested on 3.14 and 3.15), packaged with hatchling (version is read from `src/pkpdsim/__init__.py`).

## Commands

```bash
# environment (uv based)
uv sync --extra dev
uv run pre-commit install
uv lock                                  # after every change of a dependency in pyproject.toml

# tests
pytest                                   # all tests, in parallel with pytest-xdist
pytest -n 0                              # in one process, e.g. for --pdb
pytest tests/test_package.py             # single file
pytest tests/test_package.py::test_version  # single test
tox r -e py3.14                          # single tox env (py3.14, py3.15 available)
tox run-parallel                         # full matrix + ty, from uv.lock (runner uv-venv-lock-runner of tox-uv, extra dev), run before opening a pull request

# lint / format / types
ruff check
ruff format
tox -e ty                       # ty type check (config in [tool.ty] in pyproject.toml)
uv run ty check                 # same check, straight from the working tree

# docs
uv run zensical build --clean --strict
uv run python scripts/llms_txt.py
uv run zensical serve
```

`develop` is the default branch and takes every change through a pull request; direct pushes are rejected by the rulesets in `.github/rulesets/` (applied with `.github/rulesets/apply.sh`), which require the `tests`, `ruff`, `ty` and `docs` checks. Continuous integration is kept minimal: `tests` runs only `py3.14`, on linux, macos and windows, every workflow cancels a superseded run (`cancel-in-progress: true`), uv caches packages and interpreters, dependabot runs monthly. Python 3.15 runs only locally. `main` only tracks the latest release and is fast-forwarded by the `sync-main` job of the release workflow, never by hand.

Release steps are in `docs/development.md`: the release is prepared on a branch, `uvx bump-my-version bump [dev|major|minor|patch]` updates `src/pkpdsim/__init__.py`, `CITATION.cff` and `tests/test_package.py` and commits without tagging, and the tag (a plain version, `0.1.0`) is created on `develop` after the pull request was merged, which triggers the release job of `ci-cd.yml`: PyPI through the trusted publisher of the GitHub environment `pypi`, the GitHub release from `release-notes/<version>.md` (archived by Zenodo) and the fast-forward of `main`.

Documentation is [Zensical](https://zensical.org/): markdown sources in `docs/`, configured in `zensical.toml`, built into the gitignored `site/`. The API reference is rendered from the docstrings by mkdocstrings; a page in `docs/api/` is just `::: pkpdsim.<module>`. `scripts/llms_txt.py` runs after the build and writes `llms.txt`, `llms-full.txt` and the markdown of every page into `site/`. The pages of the PBPK library (`docs/pbpk/`) have generated tables (`scripts/pbpk_tables.py`), tested equations and inline SVG diagrams, see `pbpk/` below.

## Architecture

`src/pkpdsim/__init__.py` holds the version and nothing else, so `import pkpdsim` stays free of the heavy dependencies (`tests/test_package.py` checks it); every topic is a module of its own which a model imports directly. The content of the modules moved unchanged from the shared modules of pkdb_models (`pkdb_models/models/{templates,annotations,data,pkpd}.py` and the license files of the models) in 0.1.0, so that the SBML the models create stayed the same; 0.2.0 corrected the annotations and the license of the terms of use. A change of a text, a creator or an annotation changes the SBML of every model which uses it; the release notes name such a change.

**`templates.py`.** `creators` (a list of `sbmlutils.factory.Creator`, the model history of the SBML) and `terms_of_use` (markdown which the models append to their notes: the copyright of the year of the import, CC BY-SA 4.0, the license of the COMBINE archive, the disclaimer), filled from the private template `_TERMS_OF_USE` and the first creator.

**`annotations.py`.** `compartments`, the annotations of the recurring compartments keyed by their abbreviation in the models (`li`, `ki`, `gu`, `ve`, `ar`, `po`, `urine`, ...): lists of `(BQB qualifier, "collection/term")` pairs, which sbmlutils resolves via identifiers.org and writes as RDF. `tests/test_annotations.py` checks that every resource is written as `collection/term`, the collection is in the identifiers.org registry and the term matches its pattern (UBERON with seven digits, the registry accepts any number); whether a term means what its key says is checked against the ontology by hand, the comment behind a resource is its label.

**`data.py`.** `studies_dir()` returns the folder `studies` of a checkout of pkdb_data: the path of the environment variable `PKDB_DATA` (the constant `PKDB_DATA`; an empty value counts as unset), else `../pkdb_data` relative to the working directory; a folder which does not exist raises `FileNotFoundError` naming both, and a set variable which points nowhere is an error even when the default exists. `collect_tsv_files(source_dir, target_dir, filter_study=None, *, studies=(), keep_files=False)` writes the data of every study folder (and of the further folders `studies`, e.g. of another substance) into a folder of the same name in `target_dir` as the hidden tables of study format 1 which the experiments read (`.<study>_<source>.tsv`) and reports every file on the rich console of sbmlutils (it is a step of the `data/collect_data.py` script of a model): a study of format 2 is read with `pkdb.prepare` (`prepare_study`, the vocabulary of the checkout's `vocabulary.lock.json`, the reading and validation of `pkdb check`), its reported measurements become one table per source with `MEASUREMENT_COLUMNS` (individuals with their mean in `value`, a digitized error bar as the `sd`/`se`/`gsd` it names, the missing `sd`/`se`/`cv` calculated with `pkdb.domain.statistics.complete_statistics`, an output without a label labelled by `_label` from measurement, substance, tissue, interventions and subject, with the source appended when another source of the study has the label, a row with a `gmean` and no `mean` of the calculation `geometric mean` (`_calculation_type`; PK-DB defaults a group to `sample mean`), a row below the LOQ without a central value and with the calculation of its curve, the curator 0 of a curve of geometric means left out (`_series_calculations`), the interventions in the natural order of the format 2 cell, the records PK-DB normalizes or calculates left out) its scatters one table per source with `SCATTER_COLUMNS` (a point per row, the values in `x_value`/`y_value` and `x`/`y`, the time and interventions of each axis in `x_time`/`x_intervention`/..., the name of the scatter as `label`, count 1 for an individual or for points of a group with the same interventions and times, else the count of the group; `<source>Scatter` when the source also has measurements), plus `TabGroups`, `TabIndividuals` and `TabInterventions` (`study_tables`, `write_study_tables`, which replaces the earlier tables of the study unless `keep_files`); the counts are nullable integers (`INTEGER_COLUMNS`); a curated label which is no SId, the same output in two sources and the dropped curator 0 are a `CollectionWarning`; the hidden `.*.tsv` files of a study of format 1 are copied; another format is a `ValueError` before anything is written. `database_differences(study_folders, client=None)` compares the studies with a PK-DB server by the `source_digest` of their sources (`DatabaseDifference`; 404 is a difference, other client errors are raised). `mean_of_individuals` and `sampling_times` are helpers of the experiments on the tables. `pkdb` (python >= 3.14) is imported inside the functions, so `import pkpdsim.data` stays light; the tests read copies of `hydrochlorothiazide/Patel1984` and `Nilsen1989` (scatters) in `tests/data/pkdb_data`.

**`initial_values.py`.** `init_concentrations_changes(r, skey, value)` and `init_amounts_changes(r, skey, value)` return the changes (`{"[Cve_x]": value}` for concentrations, `{"Cve_x": value}` for amounts) which set a substance to the same value in every tissue of a roadrunner model, the urine excluded; `get_species_keys(skey, species_ids)` is the naming pattern `^[AC][a-z]+(_plasma)*_<skey>$` of the ids of the top model. sbmlsim takes the changes as `preinit_changes`.

**`timecourse.py`.** `SimPart(tend, changes, steps)` and `Simulation(sid, title, parts)` describe a simulation of a roadrunner model in parts, `run_simulation(r, sim)` resets the model (`resetAll`), runs the parts one after the other (the changes of a part set at its start with `setValue`, its timecourse `simulate(0, tend, steps)` from the state of the part before) and concatenates their timecourses into one `DataFrame` of the `timeCourseSelections`, the time continued over the parts (the index of each part starts at 0); it logs the integration time. The one runner of the tissue and perfusion models of pkdb_models (`tpm.spt`, `tpm.fat`, `misc.zonation`, `misc.pvl`, the zonation of gdeobdtpa), which had diverging copies with different default steps (pkdb_models#118): `steps` has no default. The script which runs a model loads it and sets its tolerances and selections. Not to be confused with the command `run_simulation` of a model package (`cli.py`, `run.py`), which runs the simulation experiments of sbmlsim.

**`licenses.py`.** `License` (`StrEnum`, `CC_BY_SA_4_0 = "cc-by-sa-4.0"`, `MIT = "mit"`, `filename`), `license_text(license, copyright=None)` and `write_license(directory, license, copyright=None)`. The texts are the resources `src/pkpdsim/resources/cc-by-sa-4.0.txt` (byte-identical to the files of the models) and `mit.txt` (the MIT text whose first line is the placeholder `Copyright (c) <year> <copyright holders>`, which `copyright`, e.g. `2024-2025 Michelle Elias & Matthias König`, replaces). The files are written in UTF-8 with LF line endings on every platform; `.gitattributes` keeps git from converting the resources and the whitespace hooks of pre-commit exclude them (the CC BY-SA text ends with an empty line). `tests/test_licenses.py` pins the sha256 of the files of three models of pkdb_models.

**`model.py`.** `PKPDModel` (frozen dataclass) describes a model once, in the `__init__.py` of its package: `name`, `package` (`__name__`), `title`, the paths (`path`, `model_path`, `data_paths`, `archive_path`), the references `factory`, `experiments` and `fit_definitions` (`"module:attribute"`, resolved on use by `resolve`; a reference which starts with a dot is relative to `package`, a malformed one fails when the object is created, a missing attribute names the reference), `SimulatorSettings` (absolute tolerance as a float or an sbmlsim `AbsoluteTolerance`, relative tolerance, `n_workers`: `1` serial by default, a number a pool, `None` sbmlsim's choice; a positive int or `None`, else `ValueError`), `FigureSettings` (derives from sbmlsim's `FigureSettings`, so its fields have sbmlsim's defaults and are given by position as in sbmlsim, plus the keyword-only `formats` (SVG only by default, `("svg",)`, pkdb_models#383) and `savefig_dpi`; `sbmlsim_settings()` is the plain sbmlsim instance a run hands to every figure, `rc_params()` the matplotlib settings of a run; nothing is applied to the process, there is no `applied()` and no `FIGURE_ATTRIBUTES`), `reduced_selections`, `save_results`, `fit_identifiability` and the `ExtraAction`s a model adds to `run_simulation`. `CheckSettings` (frozen, keyword-only, hashable) is `PKPDModel.checks`: the known exceptions of the tests, `not_registered` and `not_importable` (name to reason) and `one_at_a_time` (the reason why the experiments run one at a time; an empty reason is a `ValueError`). `pkpdsim.model` imports `sbmlsim.plot` at runtime, because `FigureSettings` derives from sbmlsim's (about 0.7 s of import time, 0.014 s before: the cost of `sbmlsim.plot`, which a model package imports anyway). `run_experiments` and `run_simulation_experiments` run experiments from a script; the model has no entry points of its own, the commands of `cli.py` resolve it by its package.

**`run.py`.** `run_experiments` and `run_simulation_experiments`: the run of experiment classes with the settings of the model (`create_simulator` makes the sbmlsim `Simulator` of `SimulatorSettings`, `simulator=` replaces them for one run, the figure settings of the model go to sbmlsim's run and the `rc_params` into a matplotlib `rc_context`); a relative output directory is below the simulation results of the model. A run which has a failed experiment or figure writes the report and collects the figures first and then raises `sbmlsim.experiment.ExperimentRunError`.

**`cli.py`.** The commands as functions of a `PKPDModel`: `run_command` (actions `factory`, `simulate`, `all`, `list_experiments` and the extra actions; `--experiments`, `--formats`, `--results-dir`, `--workers` (a number, `auto` or `model`, `parse_workers`; an extra action gets the resulting `SimulatorSettings` as `options.simulator`), `--open`; a failed run collects its failures, the remaining actions run and the command prints them and exits with 1), `fit_command` (the options of `sbmlsim.fit.cli.fit_cli` plus the identifiability options), `report_command` and `identifiability_command`. The console scripts (`run_simulation_main`, `run_fit_main`, `run_report_main`, `run_identifiability_main`, in `[project.scripts]`) all go through `main(name, argv)` and `COMMANDS`: the first argument is the dotted model package, `resolve_model` imports it and takes its `MODEL` (`ModelNotFoundError`, a usage error with exit 2, for a name which is no dotted package, a package or parent which is not found, no `MODEL`, a `MODEL` which is no `PKPDModel` or of another package; any other import error propagates with its traceback), a fit command needs fit definitions, the rest of the arguments goes to the command of the model, whose `prog` is `<command> <package>`; `--help` without a model prints the usage of the command (docs page `commands.md`).

**`fit.py`.** `default_fit_settings` (`data_at_change` is sbmlsim's `DataAtChangeType.BEFORE`, the state before a change), `mapping_metadata` (the check of the metadata type, `PKPDMappingMetaData` by default, `TypeError`) and `observable_id` (the `Data.index` of the observable of the mapping); the filters `metadata_filter(metadata_type=PKPDMappingMetaData, /, *, excluded=None, **allowed)` (`MetadataFilter`, checked against the fields of the dataclass when it is built; the class is positional-only and passed only for a local extension; a single value, an empty set, an unknown field and an instance instead of the class are errors) and `observable_filter` (`ObservableFilter`); `select_mappings(model, experiment_classes, filters, outliers, validation)` selects with sbmlsim's `FitMappings` using the paths of the model object.

**`metadata.py`.** The one vocabulary of the fit mappings of all models, 13 `StrEnum`s: `Tissue`, `Route`, `Dosing`, `Fasting`, `ApplicationForm`, `DataType`, `PKPDData`, `Health`, `Coadministration`, `Genotype`, `Phenotype`, `AdministrationSite` and `SamplingSite` (the site of a blood sample, `ARM_VEIN` the default, the observers of `pkpdsim.pbpk`), with the conventional members `HEALTHY`, `NONE` (nothing coadministered) and `NR` (not reported); a member has one name and one value in every model, a study which needs a new member adds it here, and a member whose meaning is not plain from its value is defined by a comment. The values are readable text (no `_`, a genotype starts with its gene) and API as much as the names: models look members up by value (`Genotype(f"CYP2C9 {genotype}")`, `Route(route)`). `PKPDMappingMetaData` is the keyword-only dataclass of `MappingMetaData` with 13 fields: `tissue`, `route`, `application_form` (default `NR`), `dosing`, `fasting` (`NR`), `health`, `coadministration` (`NONE`), `genotype`, `phenotype`, `administration_site`, `data`, `data_type` (all `NR`), `sampling_site` (`ARM_VEIN`, appended last so the subclasses of the models stay valid); `to_dict` gives member names in the order of the fields. A model uses the class as it is and extends it only for a facet no other model has, with a subclass in its `fitting/mapping_collections.py` which adds fields and neither redefines a field nor repeats a vocabulary (e.g. a diplotype of the subjects).

**`experiment.py`.** `PKPDSimulationExperiment`, the base of the experiments of a model: bound to the model object by `pkpd_model` (a `TypeError` without), `selections`, `Mr`, `labels`, `units`; provides `models`, `tasks` (from the simulations `initialize` created), `default_changes` (none), `data`, `load_dataframe`, `load_dataframes_by_substance`, `figures_by_sid`, the method `to_sid` and the impairment and PK maps as class attributes. `to_sid(text)` (module function) maps a text to an SId, one character for one (a decimal point between two digits is `p`, every other character outside `[A-Za-z0-9_]` is `_`) and checks neither the leading character nor an empty text, since a text may be a part of a key (sbmlsim checks the whole key at initialize); the method of the base raises a `ValueError` naming both texts when two texts of an experiment give one SId. `data_units` (class attribute, name in the data to the definition `<name> = <expression>`) defines the units of the data which sbmlsim lacks (an international unit) with `define_unit` (raises a `ValueError` for a name which is defined with another value, since sbmlsim's registry is one per process and ignores a redefinition, so the name carries the model and the substance, `IU_ramipril_renin`, and for an expression pint cannot evaluate) in `initialize`, before the data are read, so a refused definition fails its experiment and not the run (sbmlsim's runner creates the experiments outside of its error handling; a loader called without `initialize` defines them on its first call), and the loaders rename them in the unit columns with `rename_units` (the unit alone or after a metric prefix), after `add_gmean_unit` gave the rows with a `gmean` their `unit` as `gmean_unit` (sbmlsim's `DataSet.from_df` reads `unit` only for `mean`, `value` and `median`); `data_unit_names()` (public, read-only mapping, defines the units on its first call) gives the names for a table which a model reads itself (apixaban's scan of the parameters). `add_doses(times, doses, model="model")` returns the `Change` of repeated doses which add to their dose states (`"PODOSE_x + <dose in the unit of the state in the loaded model>"`), so the rest of earlier doses stays (pkdb_models#105); `ValueError` for a model which is not loaded.

**`pk.py`.** `PK_LABELS`, `PK_UNITS`, `nca_frame(result)` (a row per point: its position, every parameter with `<name>_unit`, `nca_flags`) and `scan_nca(res, key, *, dose, route, substance, lloq_fraction=None, options=None)`: the non-compartmental analysis of pkpdutils of a timecourse at every point of a scan as one batch (`ScanResult.to_timecourses`, `pkpdutils.nca`, the per-sample `lloq` relative to the maximum of every point), the parameters of `nca_single` per point to 1e-12, about 40 times faster for 200 points (pkdb_models replaces its per point loops of `nca_single`).

**`scan.py`, `sensitivity.py`.** `scan.single_dimension`, `start_values(res, key)` and `end_values(res, key)` (the first and the last value of a timecourse at every point, over the dimensions of the scan, on a grid and ragged alike: the last finite time of a point of the ragged layout of the steps of the integrator, pkdb_models#381), `state_after_changes(res)` (since 0.5.3: the whole result on its time points without the repeated ones, the state after a change, `res.interpolate(np.unique(res.time_points()))`) and `point_timecourse(res, key, /, **point)` (positional `res` and `key`, so a dimension of any name is a position) give the timecourse of a point of a sbmlsim 0.9 `ScanResult` as sbmlsim 0.8 gave it (the state after a change only), for the PK of the scans of a model. `sensitivity` is the table of the parameters of a sensitivity analysis which sbmlsim 0.9 dropped (`parameters_from_sbml`, `set_bounds`, `set_relative_bounds`, `parameters_to_df`, `write_parameters` with `parameters.tsv` and `parameters.tex`, which needs jinja2) plus `distributions` (uniform in the bounds, the input of a global design), `free_parameters(parameters, simulations)` (the parameters which no simulation of the groups sets, in `preinit_changes` or a `Change`, logs the others; a global design must vary only these, sbmlsim 0.8.5 left the others out) and `sample_size` (the environment variable `PKPDSIM_SENSITIVITY_N` replaces the sample size for a smoke run). Since 0.5.2 it is also the runner of the sensitivity scripts of the models (eleven of the twelve; simvastatin keeps its own design, icg's `sensitivity_debug.py` and `sensitivity_parameters.py` stay outside), which the ported scripts had copied (~180 lines each): `SensitivityRunner` (frozen, keyword-only: `model`, `parameters` (a function, called by a run), `outputs`, `observables`, `analyses` by name, `default` (at least one), `seed` 1234) with `run(names, *, path, subfolder, simulator)` (the parameter table into `model.results_dir / "sensitivity"` or `path`, the results of every analysis into `<analysis>/` (see below), below `subfolder` if given while the table stays, e.g. dulaglutide's `single`/`multi`; the simulator of the model with `n_workers=None`), `parse_command_line(argv, *, choices)` (`CommandLine(analyses, choices, workers)`, `--workers N` since 0.5.3: an int >= 1 caps the pool via `simulator_settings(workers)`, `0` or absent leaves `n_workers=None`; the names and a script's own words in any order, argparse without `choices` because python 3.13 checks the default of `nargs="*"` as one choice; an unknown or repeated word exits 2) and `main(argv)`; `run_subfolders(runners, names, *, subfolders, path, simulator)` runs a runner per simulation into `path/<subfolder>`, the parameter table written and printed once (runners of one model with equal parameter tables, everything checked first); `SensitivityOutput(uid, name, observable=uid)` (the uid names the outputs in the tables and the file names, the name labels the figures and heatmaps, the observable is the id in the result, e.g. `[Cve_api]_cmax` and `Cve_api_cmax`), `SensitivityGroup(uid, name, simulation, color=None)` (`color` for the figures of the sampling which compare the groups), and the closed set of analyses `LocalAnalysis` (`delta` 0.01 in (0, 1)), `SamplingAnalysis` (`n` 1000), `FastAnalysis` (`n` 1000, > 64), `SobolAnalysis` (`n` 4096, a power of two), each with its own `groups` and varying `free_parameters` of them (the private hooks `_check`, `_run`); a configuration is checked when it is created, and at the start of a run, before anything is written, the names, the subfolder, the varied parameters and their distributions and the numbers of samples of `PKPDSIM_SENSITIVITY_N`; one result per quantity (the maintainer's ruling: same parameters and outputs as before, the numbers differ by construction, the artifacts a manuscript uses must not), the files of sbmlsim 0.8.5 into `<analysis>/`: local `local_d<delta>_nvar<n_var>_<k>_<group>.tsv|.png` (`Sij` the mean of `normalized` over the designs of `delta * k / n_var`, `n_var` 3, three scans per group), sampling `sampling_N<n>.tsv`, `_compact.tsv`, `.tex` (statistics of 0.8.5 with `U`, `std` of the population) and the box/violin/points figures `_sensitivity_samples.png`, `_sensitivity_outputs.png` in the group colors, fast/sobol `<prefix>_sensitivity_<k>_<group>_S1|ST.png` heatmaps and `..._<o>_<output>.png` (`plot_indices`); per group into `<analysis>/<group>/` only what 0.8.5 wrote no file of: `samples.tsv` of the sampling and `<output>.S1|ST.tsv` of fast/sobol (the copies' `<output>.normalized.tsv`, `normalized.png`, `summary.tsv` with its quantiles, `distributions.png` and `<output>.png` are not written, and `SamplingAnalysis` has no `quantiles`); heatmaps label `uid: name` and output names (`_labelled`), cutoff 0.05 unclustered, and show every parameter when none reaches the cutoff (`plot_heatmap` would refuse); the classifications of sbmlsim (0.9.5, sbmlsim#311) give `None` for `NaN` and classify `|U|`, so `_classes` writes empty classes for `None` and no workaround is left (an infinite value, e.g. `U` of a median of zero, is `high`, where the 0.5.2 to 0.5.4 workaround left it empty); not reproduced: the `.pkl` caches of 0.8.5, separate samples per group, the overlaid one-scale bars of 0.8.5 (`plot_indices` draws S1/ST side by side on a scale per output). Since 0.5.4 its figures are drawn on `matplotlib.figure.Figure`, never pyplot (a pyplot figure of TkAgg aborts the process next to a pool, `main thread is not in main loop`; tests have the fixture `no_pyplot`). `import pkpdsim.sensitivity` takes about 1.3 s (roadrunner and `sbmlsim.simulation` as before; the runner's matplotlib, `sbmlsim.sensitivity` and `pkpdsim.model` add about 0.05 s), which a script that only writes the table of the parameters pays as well.

**`uncertainty.py`.** The uncertainty of the fitted parameters of a model and the bands of its predictions (docs page `uncertainty.md`). `adopt_fit(fit_dir, fits_dir, force=)` (`run_fit <package> --adopt <fit id> [--force]`) copies the record of a finished fit (`RECORD_FILES`: `parameters.json` and `optimization_result.json` required, `identifiability.json` or `fisher.json` required, their tables, the metrics, `report.txt`, the methods report `report.pdf` with its Typst source `report.typ`, `references.bib`, `references.csl` and the figures it shows in `plots/`; not the runs, the other figures, the LaTeX sources, HTML) into `PKPDModel.fits_dir` (field `fits_path`, default `factory_dir.parent / "fits"`, tracked with the model); `PKPDModel.fits` lists the adopted fits and `fit_records()` reads them (`FitRecords`, a parameter of two fits or of no fit raises). `FitRecord.load` gives a `ParameterUncertainty` per fitted parameter: value and unit of `parameters.json` (units of the model), bounds and scale of `optimization_result.json` (converted from the unit of the `FitParameter` with pint), the profile CI of `identifiability.json` (open side `None`, `z = sqrt(chi2(alpha, df))`), standard error and CI of `fisher.json` (`FisherInformation.from_dict` of sbmlsim), the Fisher information as the fallback for a parameter without profile. `distribution()` is the distrib formula of the draws: on a log scale `lognormal(ln v, sigma_ln, lb, ub)` with sigma the mean of the closed half widths in the scale divided by z, `uniform(lb, ub)` without a closed side, on the linear scale `normal(v, sigma, lb, ub)`, the Fisher fallback with sigma the standard error; `uncertainty(unit)` the sbmlutils `Uncertainty` (`confidenceInterval` span, `standardError` from the delta method, `distribution`, provenance in the notes); `FitRecords.parameter(pid, unit=)` the kwargs `value`, `uncertainties`, `unit` of a factory `Parameter`. Comp flattening keeps the uncertainty. `parameter_distributions(sbml)` reads the `distribution` children of the flat model into sbmlsim distributions (`distribution_from_formula`: lognormal/normal with 2 or 4 arguments, uniform with 2; distrib's lognormal has mu and sigma of ln), `uncertainty_dimension(sbml, draws, seed)` draws them with `sampling.lhs` into the dimension `uncertainty`. `run_simulation <package> --uncertainty [--draws 100] [--seed 1234] [--quantiles 0.05 0.95]` (`UncertaintySettings`) draws once per run (`UncertaintyRun.create`, in `run._run`), passes the run as the setting `uncertainty` of the runner (`SimulationExperiment.settings`) and writes into `results_dir / "simulation_uncertainty"` (`PKPDModel.uncertainty_dir` for a relative directory); `PKPDSimulationExperiment.initialize` calls `apply_uncertainty` (every simulation a `Scan` over the draws, a scan with the draws appended, a target which the simulation or a dimension sets is left out of its draws and a simulation without draws runs once; every curve of a task over the draws becomes a `Band` with the name and colour of the curve, a curve of more than one `over` dimension raises) and checks the figures again; `PKPDSimulationExperiment.uncertainty` is the run or `None` for the figures an experiment draws itself, with `scan.point_band` and `scan.scan_dimensions`. `check_fit_parameters(model)` (in `testing.check_model`) fails a parameter of an adopted fit which is missing in the flat model, has another value (rtol 1e-12) or no distribution.

**`reports.py`.** The reports of the adopted fits (`run_report <package> --adopted [-o DIR] [--no-mapping-figures]`, intercepted in `report_command` before `report_cli`, which requires files of parameter sets): `adopted_record(model, fit_id)` is the record of an adopted fit in `fits_dir` (`ValueError` for an id which is no fit id or a subset without fit definition, `FileNotFoundError` for a record without `parameters.json`; `pkpd_release` checks every adopted fit with it), `adopted_reports(model, output_dir)` writes the report of every fit of `model.fits` from its record with `sbmlsim.fit.cli.report_from_records` and the context of the model (`fit.records_context`) into `output_dir / <fit id>` (`model.report_dir` by default): the HTML report, `report.pdf` with its Typst source and the figures. `fit.fit_subset(fit_id)` is the subset of an id (`^(?P<subset>.+)_\d{8}_\d{6}__[0-9a-f]{5}$`, `ValueError` otherwise and for `/`, `\` or `..`, so that an id is safe as a folder name). The tests share the adopted toy fit of `tests/conftest.py` (`toy_fit`, `fits_dir`).

**`impairment.py`, `pk.py`.** The presets of the renal function (`RENAL_FUNCTION`, `RENAL_FUNCTION_GFR`, `RENAL_FUNCTION_90`), the cirrhosis and the cardiac function with their colors, and `PK_LABELS`/`PK_UNITS`; the values are those of the models, the floats bit-identical. `CHILD_PUGH` and `HEART_FAILURE` (with `HEART_FAILURE_COLORS`) map the classes onto the severities `CP_severity` and `HF_severity` of the models built on the PBPK library (`pkpdsim.pbpk.impairment`).

**`testing.py`.** The tests of a model as functions: `check_registry`, `initialize_experiments`, `run_all_experiments`, `start_fits` with the helpers `experiment_modules`, `defined_experiments` and `registered_experiments`; a check which fails raises one `AssertionError` which names every failure (the experiments which cannot be initialized, the failed experiments and figures of a run, also with `one_at_a_time`). The exceptions are read from `model.checks` (`CheckSettings`); one which no longer applies fails the test. `check_model` also checks the name against the package, that `model_path`, the factory directory and `archive_path` lie below `path`, and that the data paths exist.

**`profiling.py`.** `--profile` after the model package of a command (handled in `cli.main`, listed in `command_parser`) runs the command under the sampling profiler of python 3.15 (`profiling.sampling`): `run_profiled` runs `python -m profiling.sampling run --binary -o profile.bin -m pkpdsim.cli <command> <package> ...` and replays the samples into `flamegraph.html`, `heatmap/`, `profile.pstats` and `summary.txt` in `profiling/<command>_<time>/` of the results of the model (`profile_dir`); the command's exit code comes back through the file of `PKPDSIM_PROFILE_EXIT_CODE` (`record_exit_code` in the `__main__` of `cli`), since the profiler exits with 0; before 3.15 `--profile` is a usage error (`profiler_available`). The tests of a profiled run are skipped before 3.15.

**`verify.py`.** The command `pkpdsim-verify` (subcommands `dump`, `compare`, `ranges`, `fits`, `definitions`, `settings`, `png`, `sbml`) and `describe`/`ModelInfo`. `--model` is a dotted package; a package without `MODEL` exits with 2 (`describe` raises `ValueError`). A dump records the `versions` of sbmlsim and pkpdsim and an experiment which cannot be initialized as an error (`on_error="raise"`, exit 1). `compare` works across versions of sbmlsim: the time dimension first and the others by name, the rows of every point of a scan matched by its own times (`point_matches`; a grid shares them, a ragged result has them per point), the rows of a repeated time matched from the last one (the state after a change, which is all sbmlsim 0.8 had; two dumps with equal time vectors compare every row), a row at a time which only the old dump has is always a difference, one which only the new dump has is a difference which the results pattern `experiment/task/time` of `expected` can name; a figure of sbmlsim 0.8 is compared with the one of sbmlsim 0.9 in the form of 0.9 (`align_figures`: its setting attributes into `_settings`, `_width`/`_height` into `width`/`height`, compared with the settings and the size the new figure is rendered with apart from the run, which `figure_spec` stores as `__resolved__`; the share of a plot in the size of its figure left out; `sel`, `over`, `_bands` listed, not compared). `compare --renames FILE` applies the expected renames of a migration (metadata fields and members, added fields, strings, and `ids`, `sids`, `figure_fields` (left out at the level of the figure), `expected`) to the old dump (`load_renames`, `apply_renames`, which returns a new dump and renames the content of the parts only; a `strings` rename which merges two keys is an error, a bracket of an `expected` pattern is literal, mappings are `experiment/mapping`); `png --sids` pairs an old figure with the new figure of the SId of its name. `settings` captures what a run hands to sbmlsim (the arguments of `Simulator`, `ExperimentRunner` and the run with its `figure_settings` bound to their signatures, the changed `rc` keys, call counts; no `figure` part) and exits 2 for an incomplete run; `--atol` and `--rtol` take a float or `model`, anything else exits 2.

**`release/`.** The package `pkpdsim.release` and its command `pkpd_release PACKAGE --version X.Y.Z [--repo PATH] [--no-publish] [--pkpdsim-path PATH] [--workers N]` (`release/cli.py`, `release(model, ...)` returns the release repository) make the complete release of a model repository (`hctz-model`) from a model package of pkdb_models (docs page `release.md`). One module per stage: `settings.py` (`ReleaseSettings`, the field `release` of `PKPDModel`, standard library only), `source.py` (the checks of the monorepo and the release repository, `check_version`, `export_package`, `ReleaseError`, the `Runner` through which every git, uv, docker and gh call goes), `project.py` (the project files from the jinja templates in `resources/release`; `UV_VERSION`, 0.13.4, the uv of the Docker image and the `setup-uv` steps of the workflows of a release repository), `build.py` (`uv lock`, `uv sync --locked`, the factory, the simulations and, for a model with adopted fits, the simulations with the confidence interval and the fit reports of `run_report <package> --adopted -o results/fit_reports`, copied to `fit/<fit id>`, run in the release repository), `notes.py`, `docs.py`, `manifest.py` (`release.json`, `matches`, `changed_by_build`, `prune`, the marker `pkpd_release_build` of an unfinished build in the git folder: `start_build`, `stop_build`, which records the paths a failed or interrupted build changed, `finish_build`) and `publish.py` (`check_tools` before the build, `check_lock` after it, `head_is_release`, `tag_commit`, `publish`: the Docker image is built before the commit, the tag and the push, every publishing step is skipped when done, so a rerun finishes a failed publish). The order of `release`: checks, then (unless a publishing run finds the matching reviewed build, or `HEAD` is the release commit of the version with its tag missing or at `HEAD`, which resumes publishing whatever the source commit) `start_build`, export, project files, build, notes, docs, `prune`, `write_manifest`, `finish_build`; `--no-publish` stops there. A failed or interrupted build leaves the marker with the paths it changed, so the next run rebuilds without any cleanup and still refuses a file added by hand. The tests replace the runner and the publisher (`tests/test_release_cli.py`, git repositories of `tests/release_git.py` and the fixtures in `conftest.py`); no network, docker or gh.

**`pbpk/`.** The PBPK model library `pkpdsim.pbpk`, from which the PBPK models of pkdb_models will be built (the pilots hctz, apixaban and glimepiride first; docs section `docs/pbpk/`, the modellers' guide). A model package writes one `PBPKDefinition` (`definition.py`): its `Substance`s with the mechanism flags `Binding`, `Erythrocytes`, `Kp`/`KpMethod` (`Mode.TISSUE` default, `PERFUSION`, `PERMEABILITY`, `ftissue`, `ps`), `Excretion`, `Inhibition`, `Induction` (`substance.py`, `proteins.py`) and the endogenous `baseline` (mM, a number, `Value` or `Formula`, the parameter `baseline_<s>`: every species starts at the equilibrium of its exchange with plasma, `Kbc`/`Kp`/`K_int_pls`/`K_cell_pls`/`K_or`/`K_mu` times the baseline, as initial assignments marked `SpeciesStart`, built after the other elements of an organ (`_defer_start`) and kept as initial assignments under a dynamic parameter; a `Formula` may read top parameters and definition observers, never species, reactions, library observers, organ outputs or what a PD output replaces; without a baseline the SBML is that of f008d56, `test_the_sbml_without_baseline_is_that_of_f008d56` against `tests/pbpk/data/*.xml.gz` with `assert_reference_sbml` and `reference_definition` of `tests/pbpk/conftest.py`), its chemistry `Metabolism`, `Transport`, `CustomReaction` with `FirstOrder`/`MM`/`Hill` (`chemistry.py`; the `vmax` and by default the `k` of `FirstOrder` are per litre of organ, `FirstOrder(k, per_volume=False)` a clearance of the whole organ), defined once per organ, its `Variants`, `Route`s (`routes.py`), `PDComponent`s (`pd.py`), sex, population, arm vein preset, the `dynamic` parameters, its own `observers` (`Observer`, assignment rules of the top model after the library's, checked against the composed body: values of the top model, built-in functions, a state read) `creators` (sbmlutils `Creator`, the model history) and `parameters` (`ModelParameter(sid, value, unit, name, notes)`, constants of the top model which no field of the library holds, a number, a `Value` with the uncertainty of a fit or a `Formula`, read by the formulas, the observers and the custom reactions; an organ reads an id of the top model which a custom reaction reads through an input port under the same id, `OrganBuilder._custom_inputs`, and names an id which is neither local nor a constant of the top model; an id of the physiology or an organ submodel is refused by `validate`, any other id of the body (top model, submodels and model definitions of organs and PD components), the id of an observer of the definition and a local id of an organ which is no input under the same id by `compose` (`_parameter_problems`, `_Top.couple`), top formulas which read each other in a cycle as well (`_formula_cycles`); without parameters the SBML is that of f008d56); the organ-keyed fields and the sex may be given as text (`"adipose"`, `"female"`) and are normalised to `Organ`/`Sex` in the dataclasses; `build(definition, output_dir)` (`builder.py`) validates it, composes the comp model (a top model with physiology, pools, substance parameters, sinks, dose states and observers, one submodel per organ, every port and replacement generated from the organ's `Boundary`), writes `<sid>.xml` and flattens it into `<sid>_flat.xml`; `PBPKDefinition.combine` couples definitions into one physiology. The parts: `physiology.py` (ICRP 89 male/female references of `data/physiology_human.toml`, Huisinga 2012 scaling from `BW`/`HEIGHT`, everything that depends on parameters only an initial assignment, sex a build choice), `populations.py` (reference individuals and covariate distributions, never `distrib`), `organ.py`/`organ_builder.py`/`parts.py`/`distribution.py`/`placement.py` (the standard organ with collapsing, the coefficients, the placement of the chemistry, inhibition rate laws and turnover states; every metabolism and transport of the kidney runs with the tubular capacity `1 - f_tubular + f_tubular*f_renal_function`, `KI__f_tubular` 1, the intact nephron hypothesis; the kidney exposes the urinary excretion rate `Rurine_<s>`), `variants/` (zonated liver, nephron kidney, segmented intestine (default) and single lumen, the registry), `impairment.py` (`CP_severity`, the `f_renal_function`/`eGFR` stages and `HF_severity` as factor vectors of `data/impairment.toml`, the switch `CKD_hepatic` for the hepatic proteins in CKD), `observers.py` (pool, free, blood, hepatic vein, arm vein `Carm_<s>`, the default fit target), `experiment.py` (`PBPKSimulationExperiment`, the base of the experiments of a library model: `healthy_gfr(model_path, *, bw, height, hf_severity)` reads `GFR_base` in ml/min from a one-minute sbmlsim simulation with the covariates in `preinit_changes`, cached per model file and individual; the classmethods `healthy_gfr` and `renal_function(clearance, ...)` on the model of `pkpd_model`, a `ValueError` outside of `renal_function_range` (0, 2); `renal_map` a `ScaledRenalMap` of `RENAL_FUNCTION_GFR`, the classes keep their GFR in ml/min, `preset*101/healthy GFR`, lazy and bound per class as a non-data descriptor, so importing experiments loads no model and a subclass with another model gets its own GFR; `cirrhosis_map` `CHILD_PUGH`, `cardiac_map` `HEART_FAILURE`; its names are exported from `pkpdsim.pbpk` lazily by a module `__getattr__`, so `import pkpdsim.pbpk` imports no sbmlsim, `test_importing_the_library_imports_no_simulator`), `sinks.py`, `kp.py` (Rodgers & Rowland), `annotation.py` (SBO and PBPKO on every element), `ids.py` (the one id scheme), `values.py`/`data.py` (`Value` with a `source` key of `data/sources.toml`, `ModelChoice` where no publication gives a number). `build` writes SBML L3V2 (the level of the models of pkdb_models) and every initial assignment carries a name and an SBO term (`annotation.initial_assignment`), so a build logs no sbmlutils warning (`test_build_logs_no_sbmlutils_warning`). The load time is guarded twice: `test_rules_read_a_state` (no assignment rule of the flat model depends on constants only, the cause of the 28.8 s compile) in every run, and `test_load_time` (under 10 s CPU), which skips itself inside pytest-xdist workers and runs as the second command of tox (`pytest -n 0 tests/pbpk/test_builder.py::test_load_time`), so continuous integration measures it serially. The docs are tested: `tests/docs/test_pbpk_equations.py` builds toy definitions and finds every line of an ` ```equations ` fence of `docs/pbpk/*.md` (`<id> = <formula>`, `<id>: <reactants> -> <products> = <formula>`, `d(<id>)/dt = <formula>`, placeholders `<s>`, `<o>`) by id in the comp model with the same math (parsed, units of numbers dropped); `tests/docs/test_pbpk_ids.py` checks the id table of `docs/pbpk/index.md` against `pkpdsim.pbpk.ids`; the data tables of the pages are generated from the TOML files into the marked regions (`<!-- generated: <name> ... -->`) by `scripts/pbpk_tables.py` and `tests/docs/test_pbpk_tables.py` fails while a page is out of date (run `uv run python scripts/pbpk_tables.py` after a change of a data file). ## Conventions

- Type checking is done with [ty](https://docs.astral.sh/ty/). `[tool.ty.terminal] error-on-warning = true` means warnings fail the check, so the tree must stay at zero diagnostics. Suppress a diagnostic with a rule-specific `# ty: ignore[rule-name]`, never a blanket `# type: ignore`. ty also runs as a pre-commit hook (`--extra dev`).
- Linting is ruff with the full rule set of the maintainer's packages including the annotations (`ANN`), see `.ruff.toml`; every module, class and function of the package carries full type annotations and a google style docstring (ruff `D`), `tests/` and `scripts/` are exempt from the docstring rules.
- Modules get their logger with `logging.getLogger(__name__)` and the package never configures logging; the console output of `collect_tsv_files` is the exception, it reports the copies of a script, and its findings for the curation are `CollectionWarning`s (`warnings.warn`).
- A dependency is only added for an import of the package; the floors in `pyproject.toml` are the releases the package was tested with. The exception is a floor of a security fix of a transitive dependency: `certifi>=2026.10.19` (GHSA-6q48-6c7w-9gw2, the CA bundle of requests, which sbmlutils and pymetadata use).
- `tests/conftest.py` loads the registry of identifiers.org, which sbmlutils resolves annotations with, into the cache of pymetadata once in the controller of the session; without it the parallel workers download it at the same time and the replace of the cache file fails on Windows (matthiaskoenig/pymetadata#102).
- `tests/docs/test_snippets.py` executes every ` ```python ` fence of every page of `docs/` in the order it appears, one namespace per page, in a subprocess with warnings as errors and a temporary working directory. A fence whose first line is `# not executed` is a fragment and is skipped. An output a page pastes has to come from a real run of that snippet.
- `uv.lock` is committed and pins the local development environment (`uv sync`, `uv run`, so also `uv run ty check`), the `documentation` workflow, which runs `uv sync --locked`, and the ruff version of the `ruff` workflow; the tox environments, i.e. the test matrix and the `ty` check of continuous integration, resolve from `pyproject.toml` and do not use it. After changing a dependency in `pyproject.toml` run `uv lock`, otherwise the `documentation` workflow fails; `uv lock --upgrade` moves the lock to the newest releases. Dependabot bumps the lock monthly with `versioning-strategy: lockfile-only`, so the lower bounds in `pyproject.toml`, which users install against, are only changed by hand. The ruff and ty floors of the `dev` extra and the `rev` of their pre-commit hooks are the locked versions; update them together.
- libroadrunner links against `libpython`, which the interpreters of uv ship in their `lib` directory, outside the search path of the loader on Linux: export `LD_LIBRARY_PATH="$(uv run python -c 'import sys; print(sys.base_prefix)')/lib"` before running the tests (a system interpreter with its own `libpython` does not need it); the workflows do it in `.github/actions/setup`.
- Markdown carries no hard line wraps: a paragraph, a list item or a table row is a single line. Code fences, headings and the rows of badges keep their line structure.
- Release notes go in `release-notes/` as part of a release commit.
