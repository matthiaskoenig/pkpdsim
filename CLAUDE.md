# CLAUDE.md

This file provides guidance when working with code in this repository.

## Project

`pkpdsim` is a python package with the building blocks shared by physiologically based pharmacokinetic and pharmacodynamic (PBPK/PD) models in SBML, i.e., the models of [pkdb_models](https://github.com/matthiaskoenig/pkdb_models): what these models share moves here, so that the folder of a model imports nothing but itself and released packages ([pkdb_models#95](https://github.com/matthiaskoenig/pkdb_models/issues/95)). A library with the console scripts `pkpdsim-verify`, `pkpd_release` and the five commands of the models, `run_simulation`, `run_fit`, `run_report`, `run_identifiability` and `run_credibility`, which take the dotted name of a model package first. Requires python >= 3.14 (tested on 3.14 and 3.15), packaged with hatchling (version is read from `src/pkpdsim/__init__.py`).

## Commands

```bash
# environment (uv based)
uv sync --extra dev
uv run pre-commit install
uv lock                                  # after every change of a dependency in pyproject.toml

# tests
pytest                                   # all tests, in parallel with pytest-xdist
pytest -n 0                              # in one process, e.g. for --pdb
pytest tests/test_package.py             # single file
pytest tests/test_package.py::test_version  # single test
tox r -e py3.14                          # single tox env (py3.14, py3.15 available)
tox run-parallel                         # full matrix + ty, from uv.lock (runner uv-venv-lock-runner of tox-uv, extra dev), run before opening a pull request

# lint / format / types
ruff check
ruff format
tox -e ty                       # ty type check (config in [tool.ty] in pyproject.toml)
uv run ty check                 # same check, straight from the working tree

# docs
uv run zensical build --clean --strict
uv run python scripts/llms_txt.py
uv run zensical serve
```

`develop` is the default branch and takes every change through a pull request; direct pushes are rejected by the rulesets in `.github/rulesets/` (applied with `.github/rulesets/apply.sh`), which require the `tests`, `ruff`, `ty` and `docs` checks. Continuous integration is kept minimal: `tests` runs only `py3.14`, on linux, macos and windows, every workflow cancels a superseded run (`cancel-in-progress: true`), uv caches packages and interpreters, dependabot runs monthly. Python 3.15 runs only locally. `main` only tracks the latest release and is fast-forwarded by the `sync-main` job of the release workflow, never by hand.

Release steps are in `docs/development.md`: the release is prepared on a branch, `uvx bump-my-version bump [dev|major|minor|patch]` updates `src/pkpdsim/__init__.py`, `CITATION.cff` and `tests/test_package.py` and commits without tagging, and the tag (a plain version, `0.1.0`) is created on `develop` after the pull request was merged, which triggers the release job of `ci-cd.yml`: PyPI through the trusted publisher of the GitHub environment `pypi`, the GitHub release from `release-notes/<version>.md` (archived by Zenodo) and the fast-forward of `main`.

Documentation is [Zensical](https://zensical.org/): markdown sources in `docs/`, configured in `zensical.toml`, built into the gitignored `site/`. The API reference is rendered from the docstrings by mkdocstrings; a page in `docs/api/` is just `::: pkpdsim.<module>`. `scripts/llms_txt.py` runs after the build and writes `llms.txt`, `llms-full.txt` and the markdown of every page into `site/`. The pages of the PBPK library (`docs/pbpk/`) have generated tables (`scripts/pbpk_tables.py`), tested equations and inline SVG diagrams, see `pbpk/` below.

## Architecture

`src/pkpdsim/__init__.py` holds the version and nothing else, so `import pkpdsim` stays free of the heavy dependencies (`tests/test_package.py` checks it); every topic is a module of its own which a model imports directly. The content of the modules moved unchanged from the shared modules of pkdb_models (`pkdb_models/models/{templates,annotations,data,pkpd}.py` and the license files of the models) in 0.1.0, so that the SBML the models create stayed the same; 0.2.0 corrected the annotations and the license of the terms of use. A change of a text, a creator or an annotation changes the SBML of every model which uses it; the release notes name such a change.

**`templates.py`.** `creators` (a list of `sbmlutils.factory.Creator`, the model history of the SBML) and `terms_of_use` (markdown which the models append to their notes: the copyright of the year of the import, CC BY-SA 4.0, the license of the COMBINE archive, the disclaimer), filled from the private template `_TERMS_OF_USE` and the first creator.

**`annotations.py`.** `compartments`, the annotations of the recurring compartments keyed by their abbreviation in the models (`li`, `ki`, `gu`, `ve`, `ar`, `po`, `urine`, ...): lists of `(BQB qualifier, "collection/term")` pairs, which sbmlutils resolves via identifiers.org and writes as RDF. `tests/test_annotations.py` checks that every resource is written as `collection/term`, the collection is in the identifiers.org registry and the term matches its pattern (UBERON with seven digits, the registry accepts any number); whether a term means what its key says is checked against the ontology by hand, the comment behind a resource is its label.

**`data.py`.** `studies_dir()` returns the folder `studies` of a checkout of pkdb_data: the path of the environment variable `PKDB_DATA` (the constant `PKDB_DATA`; an empty value counts as unset), else `../pkdb_data` relative to the working directory; a folder which does not exist raises `FileNotFoundError` naming both, and a set variable which points nowhere is an error even when the default exists. `collect_tsv_files(source_dir, target_dir, filter_study=None, *, studies=(), keep_files=False)` writes the data of every study folder (and of the further folders `studies`, e.g. of another substance) into a folder of the same name in `target_dir` as the hidden tables of study format 1 which the experiments read (`.<study>_<source>.tsv`) and reports every file on the rich console of sbmlutils (it is a step of the `data/collect_data.py` script of a model): a study of format 2 is read with `pkdb.prepare` (`prepare_study`, the vocabulary of the checkout's `vocabulary.lock.json`, the reading and validation of `pkdb check`), its reported measurements become one table per source with `MEASUREMENT_COLUMNS` (individuals with their mean in `value`, a digitized error bar as the `sd`/`se`/`gsd` it names, the missing `sd`/`se`/`cv` calculated with `pkdb.domain.statistics.complete_statistics`, an output without a label labelled by `_label` from measurement, substance, tissue, interventions and subject, with the source appended when another source of the study has the label, a row with a `gmean` and no `mean` of the calculation `geometric mean` (`_calculation_type`; PK-DB defaults a group to `sample mean`), a row below the LOQ without a central value and with the calculation of its curve, the curator 0 of a curve of geometric means left out (`_series_calculations`), the interventions in the natural order of the format 2 cell, the records PK-DB normalizes or calculates left out) its scatters one table per source with `SCATTER_COLUMNS` (a point per row, the values in `x_value`/`y_value` and `x`/`y`, the time and interventions of each axis in `x_time`/`x_intervention`/..., the name of the scatter as `label`, count 1 for an individual or for points of a group with the same interventions and times, else the count of the group; `<source>Scatter` when the source also has measurements), plus `TabGroups`, `TabIndividuals` and `TabInterventions` (`study_tables`, `write_study_tables`, which replaces the earlier tables of the study unless `keep_files`); the counts are nullable integers (`INTEGER_COLUMNS`); a curated label which is no SId, the same output in two sources and the dropped curator 0 are a `CollectionWarning`; the hidden `.*.tsv` files of a study of format 1 are copied; another format is a `ValueError` before anything is written. Beside the tables of a study, `write_study_tables` (and `collect_tsv_files` for a copied study of format 1) writes the record `.<study>_study.json` (`StudyRecord`, `study_record_path`, `read_study_record`), the provenance of the data: `collected`, the day of the first collection (today for a new folder, kept from an earlier record, `None` for a folder with tables and no record, collected on an unknown day) with its `dating` (`collection`, or `git` with `dating_commit` from `scripts/backfill_study_records.py`, the one-off backfill of pkdb_models from its history: the earliest table commit or mention of the study in the python code of the model, moved back to the day of an adopted fit committed with the study present; `__post_init__` requires a dating exactly with a day, a record without `dating` reads as `collection`), `updated` (the latest collection), `released`/`pkdb_id` of the `release` of `study.json` (`None` unreleased), `source_digest` of PK-DB, `pkdb_data_commit`/`pkdb_data_dirty` of the checkout (`None` outside git), `tables` (sha256 by file, `table_digests`; `changed_tables(folder)` names the differences) and `versions`; read by the temporal validation of `credibility/temporal.py` and the study data of `credibility/studies.py`; tests of the script in `tests/test_backfill_study_records.py` on a git repository in `tmp_path`. `database_differences(study_folders, client=None)` compares the studies with a PK-DB server by the `source_digest` of their sources (`DatabaseDifference`; 404 is a difference, other client errors are raised). `mean_of_individuals` and `sampling_times` are helpers of the experiments on the tables. `pkdb` (python >= 3.14) is imported inside the functions, so `import pkpdsim.data` stays light; the tests read copies of `hydrochlorothiazide/Patel1984` and `Nilsen1989` (scatters) in `tests/data/pkdb_data`.

**`initial_values.py`.** `init_concentrations_changes(r, skey, value)` and `init_amounts_changes(r, skey, value)` return the changes (`{"[Cve_x]": value}` for concentrations, `{"Cve_x": value}` for amounts) which set a substance to the same value in every tissue of a roadrunner model, the urine excluded; `get_species_keys(skey, species_ids)` is the naming pattern `^[AC][a-z]+(_plasma)*_<skey>$` of the ids of the top model. sbmlsim takes the changes as `preinit_changes`.

**`timecourse.py`.** `SimPart(tend, changes, steps)` and `Simulation(sid, title, parts)` describe a simulation of a roadrunner model in parts, `run_simulation(r, sim)` resets the model (`resetAll`), runs the parts one after the other (the changes of a part set at its start with `setValue`, its timecourse `simulate(0, tend, steps)` from the state of the part before) and concatenates their timecourses into one `DataFrame` of the `timeCourseSelections`, the time continued over the parts (the index of each part starts at 0); it logs the integration time. The one runner of the tissue and perfusion models of pkdb_models (`tpm.spt`, `tpm.fat`, `misc.zonation`, `misc.pvl`, the zonation of gdeobdtpa), which had diverging copies with different default steps (pkdb_models#118): `steps` has no default. The script which runs a model loads it and sets its tolerances and selections. Not to be confused with the command `run_simulation` of a model package (`cli.py`, `run.py`), which runs the simulation experiments of sbmlsim.

**Licenses.** The texts of the licenses of a model are `sbmlsim.licenses` (`License`, `license_text`, `write_license`), which `pbpk.archive.create_archive` writes next to the models; the docs page `licenses.md` shows their use. The distrib formulas of the draws of a fitted parameter are `sbmlsim.distrib` (`parse`, `support`, `DistribFormula`), read by `uncertainty` and `pbpk.chemistry`; both are modules of sbmlsim without roadrunner, so `pkpdsim.pbpk` stays free of it.

**`model.py`.** `PKPDModel` is a `sbmlsim.project.Project` (a frozen pydantic model, `extra="forbid"`) and describes a model once, in the `__init__.py` of its package. The keywords of the model packages of pkdb_models are mapped onto the fields of the project by a before validator, only for keyword input (`PKPDModel(**data)` takes any keyword, so ty accepts the old keywords): `path` is `root` (the property `path`), `model_path` and `female_model_path` are the `variants` `male` and `female` (the values of `pkpdsim.sex.Sex`, the male build first; a variant which is no sex or a female first is a `ValueError`; the file of the male build as the female one is a `ValueError`), `data_paths` is `data_path` (the property `data_paths`, a tuple), `fit_definitions` is `fits` (the fit definitions of the project), `fits` as a sequence of fit ids is `adopted_ids` (the adopted fits; `adopted_fits()` maps them by subset, two fits of one subset raise), `fits_path` is `fits_dir`, `factory_path` is `factory_dir`, and a `FigureSettings` of pkpdsim as `figures` is split into `figure_settings` (`sbmlsim_settings()`) and `figures` (`outputs()`, a `FigureOutputs` of the formats and `savefig_dpi`), a plain sbmlsim `FigureSettings` goes to `figure_settings`; a keyword and its field together are a `ValueError`. `package`, `factory_dir` (the directory of the male build by default) and `fits_dir` (`factory_dir.parent / "fits"` by default) are narrowed to be always set, derived in the before validator from the raw values, relative ones relative to `root` as the fields resolve them; the factory directory lies inside the root (sbmlsim). `replace(**fields)` gives a changed copy by the names of the fields (`Project.replace`); with other `variants` or another `root` it derives the directories again when they are the derived ones and not given (as the dataclass did), a `FigureSettings` as `figures` replaces `figure_settings` too. `model_path` is the property of `Project` (the male build), `variant_path(variant)` any build. A model needs its build and its factory. `PKPDModel` keeps what is pkpdsim's: `archive_path`, `results_path` and the result directories as properties (`results_dir`, `simulation_dir`, `uncertainty_dir`, `fit_dir`, `report_dir`, `identifiability_dir`, `credibility_dir`, below the package, which phase 3 of the consolidation removes), `reduced_selections`, `save_results`, `fit_identifiability`, the `ExtraAction`s of `run_simulation` and `extra_arguments` (references checked when the model is created, an action which repeats an action of `RUN_ACTIONS` or another is a `ValueError`), `adopted_ids` (with `adopted_fits()` from them; `title` and `fit_records()` are those of `Project`), `model_paths` (`Sex` to build), `female_model_path`, `model_path_of(sex)` (a `ValueError` naming the model and `female_model_path` for a sex without build), `load_roadrunner(sex)` (a build at the level of the model, the loader of the tests of a model), `load_credibility()` (a `TypeError` for a reference which is no `sbmlsim.credibility.Credibility`), `credibility_settings` (`CREDIBILITY_SETTINGS`, see `credibility/`) and the known failures of the battery checked against `BATTERY_CHECKS` of `sbmlsim.credibility.verification` and `PK_CHECKS` of `credibility/battery.py`. The default simulator of a model is `DEFAULT_SIMULATOR`, `SimulatorSettings(absolute_tolerance=1e-10, relative_tolerance=1e-10)` of sbmlsim; the processes belong to the run, `RUN_WORKERS` (1, serial, so a script without the guard `if __name__ == "__main__":` runs) is the default of `run_experiments` and `run_simulation_experiments`, which keep their signatures of the model packages (`experiment_classes`, `output_dir`, the result a `Path`; they override `Project.run_experiments`, `ty: ignore[invalid-method-override]`) and gain `n_workers`. The fit definitions of `load_fit_definitions()` carry the level of `SimulatorSettings.jit_optimization` (`FitDefinition.jit_optimization` of sbmlsim), so the problems of the fits, their reports, the identifiability analysis, `start_fits` and `pkpdsim-verify fits` load their models at it in every worker. `SimulatorSettings`, `CheckSettings`, `resolve`, `check_reference`, `normalize_formats` and the release settings (`sbmlsim.release.settings`) are sbmlsim's (a model sets their framework, core libraries, release hook and archive, see `release/`), `fit_subset` and `FIT_ID` are `sbmlsim.fit.result`'s and `adopted_record` is `Project.adopted_record`; pkpdsim re-exports none of them. `sex.py` holds the enum `Sex` alone, imported by the model object and by the library, which re-exports it, so that neither imports the other. `pkpdsim.model` imports `sbmlsim.plot` and `sbmlsim.project` at runtime, because `FigureSettings` derives from sbmlsim's. The model has no entry points of its own, the commands of `cli.py` resolve it by its package.

**The run of the experiments.** `PKPDModel.run_experiments` and `run_simulation_experiments` call `Project.run_experiments(self, ...)` of sbmlsim (`_run`) with the settings of the model: the simulator settings of the model or `simulator=`, `n_workers` the pool of the experiments (`None` by default, a worker per four experiments, at most one per CPU) and `scan_workers` the processes of the scans (`RUN_WORKERS`, 1, serial, by default: the default of pkpdsim before step 4b of the consolidation, restored in step 5b; `None` takes `n_workers`, sbmlsim's meaning), `save_results` of the model unless given, `reduced_selections` of the model, the figure settings and formats of the project; a relative output directory is below `simulation_dir`, with `uncertainty` (`sbmlsim.experiment.draws.UncertaintySettings`) below `uncertainty_dir`, `run_simulation_experiments` collects the figures (`collect_figures=True`, `sbmlsim.project.FIGURES_DIR`, `_figures`) and returns their directory, and the messages are shown on the rich console (`log.enable_rich_logging()`). A run which has a failed experiment or figure writes the report and collects the figures first and then raises `sbmlsim.experiment.ExperimentRunError` (sbmlsim). The `run.py` of pkpdsim (`create_simulator`, which is `SimulatorSettings.simulator(n_workers)` of sbmlsim, `COLLECTED_FORMATS`) was removed in step 4b of the consolidation.

**`cli.py`.** The commands as functions of a `PKPDModel`, wrappers of the run layer of sbmlsim since step 5b of the consolidation: they keep their options and defaults, build the spec of a kind of `python -m sbmlsim.run` and run it with `sbmlsim.run.execute` (`_execute`, a `ConfigurationError` of the plan is a usage error, exit 2) on the project `<package>:MODEL` (`project_reference`, a `ValueError` for a model which is not the model object of its package, so tests make a copy the model object with the fixture `as_model` of `tests/conftest.py`, which monkeypatches `MODEL` of the package). A kind needs an empty output and writes `run.json`, `spec.json`, `summary.json` and `progress.jsonl` into it, so a command runs it into the folder of its result below its old directory through a staged swap (`_staged`: the run into `.<name>.<uuid>` next to it, the result folder of the kind moved up inside it (`_moved_up`), an earlier result renamed aside, the staging renamed into place, the earlier removed; a failed run or plan removes the staging and keeps the earlier result, the stagings a killed run left are swept and logged (`_sweep`), an `OSError` of the move-up or the swap is an exit-1 message naming the `.old` folder when it is not restored, one of the run propagates; the identifiability report's `spec.json` is rewritten to name its input after the swap, `_relocated_input`; `_overlaps` also compares with `os.path.samefile`), refuses an output which is, contains or lies inside an input, the adopted fits, the factory or a build, or contains the package or its data (`_check_out`, usage error), plans a spec first (`_execute`: a plan error exits 2, a `ConfigurationError` of the run 1), so the files are where they were: `run_command` (actions `factory`, `simulate`, `all`, `list_experiments` and the extra actions; `simulate` is the kind `simulate` into `simulation/<group>` or `custom_selection` (`simulation_uncertainty/` with `--uncertainty`, the field `uncertainty`), unknown names warned and left out (the kind refuses them), the figures collected afterwards (`collect_figure_files`), `--open` opens `index.html`; `list_experiments` is `sbmlsim.run.list_analyses`; `factory` builds in place with `create_models` (library), `--rebuild` (new) runs the kind `factory` into `results/factory` and exits with 1 for a changed output; the extra actions are called as before with the results directory (library: the results are no empty output); `--workers` (`run_workers`): `model` the kind with `min(available_cpus(), ceil(n / EXPERIMENTS_PER_WORKER))` workers (serial below), a number as given, `auto` `Project.run_experiments(n_workers=None)` of the library (the kind resolves its workers), while an extra action gets `parse_workers` (`model` is `RUN_WORKERS`); a failed run collects its failures, the remaining actions run and the command prints them and exits with 1), `fit_command` (returns the records directory by fit id; the options of `sbmlsim.fit.cli.fit_cli` plus the identifiability options and `--start JSON_OR_FIT_ID`; the kind `fit` into `<output_dir>/<fit id>` with `opid` the id, `report`, `record_adopted`, `identifiability`, `profile`, `fisher`, the start resolved to a path for a finished fit of the output (`_start`), the records moved up from `<fit id>/<fit id>`; `--name` ignored with a warning; `--strategy single` keeps the old library path (`_fit_each`, `sbmlsim.fit.cli.run_fit`); `--adopt` checks a plain `FIT_ID` with `parameters.json` in the output first, runs the kind `adopt` into a temporary directory and `adopt_fit`s its record into `fits_dir`; a failed fit moves up the records it wrote (`finally`); `--cross-validation` runs `sbmlsim.credibility.cross_validate` of the library and stores the result as `cross_validation.json` in the record of the adopted fit in `fits_dir`, where the assessment reads it), `report_command` (the kind `report` into `<output_dir>/<name or report>`, `--adopted` per adopted fit into `<output_dir>/<fit id>`; several files or a file which is no `parameters.json` go to `report_cli`), `identifiability_command` (the kind `identifiability` into `<name>/analysis` and the kind `report` of it into `<name>/report`, the report moved up into `<name>`; a file which is no `parameters.json` goes to `identifiability_cli`) and `credibility_command` (the kind `credibility` into the folder `--output_dir`, `results/credibility` by default, through the staged swap with the outputs of the kind moved up from `credibility/` (`CREDIBILITY_DIR`); `_check_out` refuses an output of its inputs, `_check_credibility_out` a file or a directory with other files than an assessment (`credibility.json`, exit 1, as `write_outputs` did); `--from-json` is the input `record` (a record may be written again into its own directory); `fates.tsv` is the table of the hook, which sbmlsim's report writes without rows also when the battery did not run, so the outputs are the ones of pkpdsim 0.19; the options of an assessment with a record and the options of the uncertainty and the variability without them stay usage errors of the parser, an invalid setting is a plan error of the kind (exit 2); an error of the declaration, the evidence, the records or the lock (`LookupError`, `ValueError`, `TypeError`, `OSError`) exits 1; `--lock` moves the lock the kind writes into its output to `sbmlsim.credibility.lock.lock_path(model)`, the folder of the model). The console scripts (`run_simulation_main`, `run_fit_main`, `run_report_main`, `run_identifiability_main`, `run_credibility_main`, in `[project.scripts]`) all go through `main(name, argv)` and `COMMANDS`: the first argument is the dotted model package, `resolve_model` imports it and takes its `MODEL` (`ModelNotFoundError`, a usage error with exit 2, for a name which is no dotted package, a package or parent which is not found, no `MODEL`, a `MODEL` which is no `PKPDModel` or of another package; any other import error propagates with its traceback), a fit command needs fit definitions, the rest of the arguments goes to the command of the model, whose `prog` is `<command> <package>`; `--help` without a model prints the usage of the command (docs page `commands.md`). `--profile` after the package runs the command under sbmlsim's profiler, `sbmlsim.run.profiling.run_profiled([command, package, ...], profile_dir(model, command), module="pkpdsim.cli")`, into `profiling/<command>_<time>/` of the results of the model; the `__main__` of `cli` records the exit code with `sbmlsim.run.profiling.record_exit_code`; before 3.15 a usage error. `PKPDModel.extra_actions` are also the `actions` of the project (`ExtraActionFunction`, a frozen dataclass with the reference, which calls the old function with a namespace of the defaults of `extra_arguments` and the arguments of the spec), so the kind `action` runs them; giving `actions` directly is a `ValueError`; an argument of the spec which is no option of the parser of `extra_arguments` is a `ValueError`, a text is converted by the type of its option.

**`fit.py`.** What the fits of the models share beyond sbmlsim: `default_fit_settings` (`data_at_change` is sbmlsim's `DataAtChangeType.BEFORE`, the state before a change), `mapping_metadata` (the check of the metadata type, `PKPDMappingMetaData` by default, `TypeError`), `metadata_filter(metadata_type=PKPDMappingMetaData, /, *, excluded=None, **allowed)` (a typed `def` calling `sbmlsim.fit.filters.metadata_filter` with the PK metadata, so the calls of the models keep their signature; the class is positional-only and passed only for a local extension) and `check_sampling_sites(fit_mappings, sites)`, which checks the resolved sampling site of every mapping against a table `{observable id: SamplingSite}` and returns one problem per mismatch or unknown observable (a model test asserts it is empty). `PKPDMappingMetaData.filter_value` (the hook of `sbmlsim.fit.objects.MappingMetaData`) gives a filter the resolved sampling site. Everything else of a fit is sbmlsim's, imported from there (no re-exports): the filters `MetadataFilter`, `ObservableFilter`, `observable_filter`, `observable_id`, `NamedFilter`, `named_filter`, `NamedMappings`, `study`, `named` (`sbmlsim.fit.filters`), `select_mappings(project, ...)` (`sbmlsim.fit.helpers`), `FIT_ID`, `fit_subset`, `fit_date` (`sbmlsim.fit.result`), `start_point`, `with_start`, `fixed_values`, `current_fixed_fits`, `recorded_fixed_fits`, `FIXED_FITS`, `remainder_problems` (`sbmlsim.fit.project_fits`; `fit_command` refuses a fit whose remainders `1 - a - b` of a build can be negative at the upper bounds, `parser.error`) and `report_context`, `records_context` (`sbmlsim.fit.cli`, the title is `Project.title`).

**`metadata.py`.** The one vocabulary of the fit mappings of all models, 13 `StrEnum`s: `Tissue`, `Route`, `Dosing`, `Fasting`, `ApplicationForm`, `DataType`, `PKPDData`, `Health`, `Coadministration`, `Genotype`, `Phenotype`, `AdministrationSite` and `SamplingSite` (the site of a blood sample, the observers of `pkpdsim.pbpk`), with the conventional members `HEALTHY`, `NONE` (nothing coadministered) and `NR` (not reported); a member has one name and one value in every model, a study which needs a new member adds it here, and a member whose meaning is not plain from its value is defined by a comment. The values are readable text (no `_`, a genotype starts with its gene) and API as much as the names: models look members up by value (`Genotype(f"CYP2C9 {genotype}")`, `Route(route)`). `PKPDMappingMetaData` is the keyword-only dataclass of `MappingMetaData` with 13 fields: `tissue`, `route`, `application_form` (default `NR`), `dosing`, `fasting` (`NR`), `health`, `coadministration` (`NONE`), `genotype`, `phenotype`, `administration_site`, `data`, `data_type` (all `NR`), `sampling_site` (`None` by default, what a study states; read the site with `resolved_sampling_site()`, never from the field: it follows the tissue without a statement by the table `_DEFAULT_SITES`, plasma, serum and blood `ARM_VEIN`, arterial blood and plasma `ARTERIAL`, saliva, urine, feces, feces and urine, bile and none `NOT_APPLICABLE`; `__post_init__` refuses a blood site on a tissue without a blood sample, `NOT_APPLICABLE` on a blood tissue and a site other than `ARTERIAL` on an arterial tissue, and `tests/test_metadata.py` classifies every member of `Tissue`, so a new member fails until it is in the table; `to_dict`, the filters and `check_sampling_sites` read the resolved site; appended last so the subclasses of the models stay valid); `to_dict` gives member names in the order of the fields. the binding in CKD per protein: albumin and AGP follow their profile of `[ckd.binding]` (`fimp_albumin_ckd`, `fimp_agp_ckd`, created only when a substance binds the protein with the CKD factor), an unknown protein the binding capacity `plasma_protein`, `Binding(ckd=False)` only for a fu which is no binding measurement or whose binding is measured unchanged in renal impairment), `observers.py` (pool, free, blood, hepatic vein, arm vein `Carm_<s>`, the default fit target; the observers of a definition, `OrganOutput`, the intestine readouts), `sinks.py`, `kp.py` (Rodgers & Rowland), `annotation.py` (SBO and PBPKO on every element), `ids.py` (the one id scheme; every public name is in `__all__` and has a row in the id tables of `docs/pbpk/index.md`, both tested), `values.py`/`data.py` (`Value` with a `source` key of `database/sources.toml`, `ModelChoice` where no publication gives a number).

**Experiments (`experiment.py`).** `PBPKSimulationExperiment`, the base of the experiments of a library model: `healthy_gfr(model_path, *, bw, height, hf_severity, cp_severity)` reads `GFR_base` and returns it as a quantity in ml/min (`renal_function` a dimensionless quantity, both for the changes of a simulation; `REFERENCE_GFR` 101 ml/min, imported from `pkpdsim.pbpk`) (it carries the factors of heart failure and of the hepatorenal reduction of cirrhosis) from a one-minute sbmlsim simulation with the covariates in `preinit_changes`, cached per model file, its modification time and the individual; the classmethods `healthy_gfr`, `renal_function(clearance, ...)`, `renal_function_limits` and `renal_map_of` on the build of the sex of the subjects (`subjects_sex(sex, simulation)`: `simulation=` the key of a simulation, whose sex `sex_of`, a classmethod, resolves from `simulation_sexes`, e.g. the group of women of a study of men; `sex=` a sex; with neither the class attribute `sex`, refused in an experiment whose `simulation_sexes` names another sex, since its subjects have no one sex and the male GFR for a woman would pass silently), `renal_map_of` the renal classes of another sex (`ScaledRenalMap.of_sex`, a map at the healthy GFR of that build, cached per bound map; a map with its own GFR has no other sex, a plain mapping is of every sex); `renal_map` a `ScaledRenalMap` of `RENAL_FUNCTION_GFR`, the classes keep their GFR in ml/min, `preset*101/healthy GFR`, lazy and bound per class as a non-data descriptor (a plain dict of the bound maps, left out when pickled), so importing experiments loads no model and a subclass with another model or another `sex` gets its own GFR (the map of a class is bound to the GFR of its `sex`); `cirrhosis_map` `CHILD_PUGH`, `cardiac_map` `HEART_FAILURE`; `equilibrated` (see the equilibration below); `molecular_weights(definition)` (the `Mr_<s>` of the substances and the parameters `Mr_<x>` of a definition as a read-only mapping of quantities in g/mole, instead of the `MolecularWeights` copied into a model); `PBPKDefinition.parameter_value(sid)` is the number of a constant `ModelParameter` (a constant of a formulation or a dose, which the experiments read instead of a copy); its names are exported from `pkpdsim.pbpk` lazily by a module `__getattr__` (and listed by `__dir__`), so `import pkpdsim.pbpk` imports no sbmlsim, `test_importing_the_library_imports_no_simulator`.

**Kidney validity (`kidney_validity.py`).** The validity of the kidney outflow lives in `kidney_validity.py` (exported lazily as well): `kidney_outflow(model_path, changes)` gives the filtered plasma water (`KidneyOutflow` with `substance=None`, `formula` `GFR` against `Qki*(1 - HCT)`, since the glomeruli filter the water whatever the substances, the tighter bound since `fu <= 1` and `BP >= 1 - HCT`; hctz 6.08 instead of 18.1) and per filtered substance a `KidneyOutflow` (GFR, net filtered plasma flow, plasma flow in ml/min, the `formula` of the net flow, `fu*GFR` with a threshold reabsorption) from the one-minute simulation of `individual_values` (cached per model file, modification time and the changes of the ids the flows depend on, `FlatModel.inputs` from the initial assignments and rules of the flat model, so a dose makes no individual; the model `loaded_model` of `flat_model.py`, compiled once per process at `O0` and shared with the equilibration and `healthy_gfr`; a model without a filtered substance, or without the GFR, `Qki` and `HCT`, is not simulated and has no bound); `simulated_individuals(simulation, model_path)` gives the individuals of a simulation or scan (preinit changes, of a presimulation as well, every simulation of a dimension of simulations, every point of the value dimensions without `at`; not a change during a simulation, also of a `dynamic` id at its start, not a timed dimension, not a scan over models, not the uncertainty draws, all listed in the docs); `PBPKSimulationExperiment.initialize` refuses an individual outside of it, each task on the model it runs (`models()`, `_model_path`), with a message naming experiment, simulation, GFR and plasma flow, `renal_function` refuses a renal function beyond it (naming GFR and plasma flow) or outside a model's `renal_function_range` (`None` by default, only narrows), `renal_function_limits(...)` the derived range (0 to the smallest plasma flow over filtered flow at renal function 1, the water included), `test_kidney_validity.py`.

**Equilibration (`equilibration.py`, `flat_model.py`).** `PBPKSimulationExperiment.equilibrated(simulation_or_scan, resets=, model=, absolute_tolerance=1e-12, relative_tolerance=1e-10, max_time=1e14)` starts a simulation from the drug-free steady state of its condition: the presimulation `SteadyState` of sbmlsim with the changes before the initialization, chosen over a hidden pre-run from a negative start, which leaves a homeostasis of 7 days 1.8 % off after 28 days (`tests/pbpk/test_equilibration.py`); the doses before the initialization (`PODOSE_`/`IVDOSE_`/`SOLDOSE_`/`Ri_`, `DOSE_PREFIXES`) move to a change at the start; the sinks `Aurine_`/`Afeces_`, the intestine readouts which nothing drains (`Aabs_<s>` and `Aapp_<s>`, `GU__Aabs_<s>` and `GU__Aapp_<s>` with the readout `Fa_<s>` alone, since an endogenous substance which reaches the lumen at its baseline is absorbed again) and `resets` are set back at the start, a key of `resets` converted as the zeros (`[sid]` for a concentration species, the quantity of a PEtab condition); it refuses a dose before the initialization and at the start, a dimension over a dose the simulation does not give, a second presimulation, and a state which grows without an outflow and is not set back (`accumulating_states`/`growing_states`, checked once per model file); the `<id>_0` of a delta is set to its value after the equilibration; the species of the drugs are set to exactly 0 at the start, `drug_free_zeros(model_path, set_ids)`, since the residue of the presimulation (1.5e-29 mM in hctz) let pre-dose zero points into the fold metrics: the species of the substances without `baseline_<s>` (by `Mr_<s>`) which start at 0 and which no reaction feeds from a species with a start (a fed reactant, a fed product of a reversible reaction, a source which reads no dose id), minus what the condition, a dimension or a change at the start sets; the direction of a reaction for the zeros is its `reversible` flag, so a `CustomReaction` which can run backwards is written `A <-> B`; no steady state by `max_time` is sbmlsim's `SteadyStateError`; overloads for `Simulation`, `Scan` and the union, so a caller with both needs no `match`. The method calls `equilibrated_simulation(simulation, model_path, resets=, ...)` with the file of its loaded model (an error is noted with the experiment): the one equilibration, also outside an experiment, exported lazily from `pkpdsim.pbpk`; the names (`EQUILIBRATION_TOLERANCES`, `DOSE_PREFIXES`, `accumulating_states`, `growing_states`, `drug_free_zeros`, `equilibrated_simulation`, `Equilibration`) have the one import path `pkpdsim.pbpk.equilibration`. `Equilibration(resets=...)` is the function with which a sensitivity group equilibrates its scans (`SensitivityGroup(prepare=Equilibration(...))`), so the generic analyses import no module of the library. `flat_model.py` is the one reader of a built model for the equilibration and the kidney validity: `flat_model(path)` parses a flat file once per process (a `FlatModel` cached by path and modification time: species, parameters, accumulating states, the drug-free candidates and started species, concentrations, reactions, filtered substances, the flows of the kidney and their inputs), `loaded_model(path)` compiles it once at `O0` with the selections of both (`FlatModel.selections`), and `math_names` is the one walker of the names of a formula.

**Docs and diagrams.** The docs are tested: `tests/docs/test_pbpk_equations.py` builds toy definitions and finds every line of an ` ```equations ` fence of `docs/pbpk/*.md` (`<id> = <formula>`, `<id>: <reactants> -> <products> = <formula>`, `d(<id>)/dt = <formula>`, placeholders `<s>`, `<o>`) by id in the comp model with the same math (parsed, units of numbers dropped); `tests/docs/test_pbpk_ids.py` checks the id table of `docs/pbpk/index.md` against `pkpdsim.pbpk.ids`; the data tables of the pages (`docs/pbpk/*.md` and `docs/database.md`, the studies and the consensus of cirrhosis) are generated from the parameter database into the marked regions (`<!-- generated: <name> ... -->`) by `scripts/pbpk_tables.py` and `tests/docs/test_pbpk_tables.py` fails while a page is out of date (run `uv run python scripts/pbpk_tables.py` after a change of a table or a study). The diagrams are hand-written SVGs in `docs/pbpk/img/`, inlined into the page with `pymdownx.snippets` (`--8<-- "pbpk/img/<name>.svg"` in a `<div class="pbpk-figure" markdown="0">`, `docs/stylesheets/pbpk.css`), so `currentColor` and the CSS variables of the theme reach them; the classes and ids of a figure start with its own prefix (`pkc-` composition, `pkr-` circulation, `pko-` organ, `pkz-` zonated, `pkg-` intestine, `pki-` impairment), since the `<style>` of an inline SVG applies to the whole page.

The tests share the flat models of the session: `tests/conftest.py` patches `pkpdsim.pbpk.builder.flat_model` for the session (`flat_model_cache`) with a cache by the sha256 of the comp file without the dates of the model history, in a folder of the session which every worker of pytest-xdist shares (about a quarter of the builds of the suite repeat a comp model); a test which checks what the validation logs is marked `uncached_build`.

## Conventions

- Type checking is done with [ty](https://docs.astral.sh/ty/). The optional extra `amici` (the extra `amici` of sbmlsim, built from source, not in the dev environment) is imported by sbmlsim only, pkpdsim never imports it. `[tool.ty.terminal] error-on-warning = true` means warnings fail the check, so the tree must stay at zero diagnostics. Suppress a diagnostic with a rule-specific `# ty: ignore[rule-name]`, never a blanket `# type: ignore`. ty also runs as a pre-commit hook (`--extra dev`).
- Linting is ruff with the full rule set of the maintainer's packages including the annotations (`ANN`), see `.ruff.toml`; every module, class and function of the package carries full type annotations and a google style docstring (ruff `D`), `tests/` and `scripts/` are exempt from the docstring rules.
- Modules get their logger with `logging.getLogger(__name__)` and the package never configures logging; the console output of `collect_tsv_files` is the exception, it reports the copies of a script, and its findings for the curation are `CollectionWarning`s (`warnings.warn`).
- A dependency is only added for an import of the package; the floors in `pyproject.toml` are the releases the package was tested with. The exception is a floor of a security fix of a transitive dependency: `certifi>=2026.10.19` (GHSA-6q48-6c7w-9gw2, the CA bundle of requests, which sbmlutils and pymetadata use).
- `tests/conftest.py` loads the registry of identifiers.org, which sbmlutils resolves annotations with, into the cache of pymetadata once in the controller of the session; without it the parallel workers download it at the same time and the replace of the cache file fails on Windows (matthiaskoenig/pymetadata#102).
- `tests/docs/test_snippets.py` executes every ` ```python ` fence of every page of `docs/` in the order it appears, one namespace per page, in a subprocess with warnings as errors and a temporary working directory. A fence whose first line is `# not executed` is a fragment and is skipped. An output a page pastes has to come from a real run of that snippet.
- `uv.lock` is committed and pins the local development environment (`uv sync`, `uv run`, so also `uv run ty check`), the `documentation` workflow, which runs `uv sync --locked`, and the ruff version of the `ruff` workflow; the tox environments, i.e. the test matrix and the `ty` check of continuous integration, too (the runner `uv-venv-lock-runner` of tox-uv, `uv sync --locked` with the extra `dev`), so a source of `[tool.uv.sources]` holds everywhere. After changing a dependency in `pyproject.toml` run `uv lock`, otherwise the `documentation` workflow fails; `uv lock --upgrade` moves the lock to the newest releases. Dependabot bumps the lock monthly with `versioning-strategy: lockfile-only`, so the lower bounds in `pyproject.toml`, which users install against, are only changed by hand. The ruff and ty floors of the `dev` extra and the `rev` of their pre-commit hooks are the locked versions; update them together.
- libroadrunner links against `libpython`, which the interpreters of uv ship in their `lib` directory, outside the search path of the loader on Linux: export `LD_LIBRARY_PATH="$(uv run python -c 'import sys; print(sys.base_prefix)')/lib"` before running the tests (a system interpreter with its own `libpython` does not need it); the workflows do it in `.github/actions/setup`. tox takes the interpreters of uv only (`uv_python_preference = only-managed`; the libroadrunner 2.11.0 wheel for 3.15 needs `__jit_debug_register_code` of a `libpython` built with the experimental JIT, which deadsnakes lacks, sys-bio/roadrunner#1406) and its inline plugin `toxfile.py` puts the `lib` of the interpreter of each environment on `LD_LIBRARY_PATH`, so `tox` needs no export (without it roadrunner loaded the system's `libpython` of the same version, a second runtime in the process).
- Markdown carries no hard line wraps: a paragraph, a list item or a table row is a single line. Code fences, headings and the rows of badges keep their line structure.
- Release notes go in `release-notes/` as part of a release commit.
